## 0. 一句话

**外壳是一层「薄、可替换、连任意节点」的 UI：它只做两件事——把命令发给节点、把节点的事件流渲染出来。** 因为它与内核解耦，同一套 UI 既能连本机节点，也能连别的设备上的节点。

---

## 1. 外壳与内核的解耦

```
   外壳（TS/Solid）                     内核（Rust 节点）
   ┌────────────────┐  ① 命令（→）      ┌────────────────┐
   │  视图渲染        │ ───────────────▶ │  处理命令→产出事件│
   │  交互/输入        │  ② 事件流（←）    │                  │
   │  本地读模型       │ ◀─────────────── │  事件日志         │
   └────────────────┘                   └────────────────┘
         统一的「命令 + 事件流」契约（本机用 IPC，跨机用 WS）
```

- **外壳不持有权威状态**：它持有的「状态」是从事件流派生的**读模型**（可丢弃重建）。
- **同一套契约**：本机进程内（Tauri IPC）与跨机（WS）是同一契约的不同适配器——这正是「换端」在 UI 层免费的根因。
- **契约需版本化**（P9）；以 **Rust 类型为单一事实源**生成 TS 类型与契约文档，收敛跨语言边界。
- **插件 UI 的每次桥调用都带宿主签发的 capability token + `Principal`**；UI 不能靠传参获得权限（与 ADR-0010 一致）。

---

## 2. 外壳形态（同一内核，多个外壳）

| 外壳 | 所处 | 说明 |
|---|---|---|
| **桌面** | Tauri 桌面壳 | 主形态（Q3：v1 优先） |
| **移动** | Tauri 移动壳 | 同一套 Solid UI，响应式重排 |
| **Web 控制台** | 浏览器 | 连服务器节点，管理/查看 |
| **无头（headless）** | 无 UI | 服务端节点默认；纯运行 |
| **TUI**（可选） | 终端 | 服务器上快速调试 |

> 外壳是**可替换、可移除**的插件（`module-map.md`）：没有外壳，节点照样跑（headless 就是例证）。

## 3. 响应式与区域（内嵌模型）

区域与插槽模型见 `plugin-system.md` §5.1（ADR-0006）。要点：

```
   桌面：            移动：
   ┌──┬────┬──┐      ┌────────┐
   │左│ 主 │右│      │  header │
   ├──┴────┴──┤      ├────────┤
   │  status  │      │  main   │
   └──────────┘      ├────────┤
   三栏布局            │  bar   │   ← 侧栏折叠为抽屉/标签
                     └────────┘
```

- **布局归外壳**：同一份声明式视图（D 档）在桌面/移动由外壳重排；插件的视图无需为每种端重写。
- **区域可被插件扩展**：插件贡献到区域，或自定义新区域（`ui.region`）供其他插件填充——**UI 自身可递归扩展**。

## 4. 从事件流派生 UI 状态

外壳订阅节点事件流，把事件折叠成**视图模型**（会话列表、运行进度、工具调用卡片…）。完整协议分四步：

- **握手**：外壳发 `hello` → 节点返回 `protocolVersion`、能力清单、插件状态版本。
- **初始快照**：外壳发 `query`，节点返回所需读模型的**快照 + 游标（cursor）**；快照与增量之间**无缝隙**——**游标之后的事件才算增量**。
- **订阅**：`subscribe(sessionId, cursor)`；断线重连 `resume(cursor)` 补齐，UI 状态自动收敛。
- **查询**：会话列表、配置、插件状态、分页历史都走 `query`（带分页 token），**不靠事件流全量回放**。

- **快照可丢弃、可重建**：UI 不持有权威状态，随时可从节点重新 `query` 得到。
- **乐观更新**：外壳可先本地渲染「命令已发出」的中间态，待事件回来再校正（如「审批中…」）。

### 4.1 流式输出与持久消息的区别

- 模型 token 流是**易失的**（`ephemeral`），不进事件日志；
- 最终消息以 `MessageAppended` 落盘，是权威记录；
- UI 必须区分「流式草稿」与「已提交消息」，重连时**丢弃草稿、从已提交消息重建**；
- 流式事件可合并、可丢中间帧（见 §4.2）。

### 4.2 慢客户端与背压

- token 流可**合并/降采样**；中间帧可丢，**状态事件不可丢**；
- 客户端跟不上时降级为「按快照 + 低频增量」，并**显式提示**（如「显示可能滞后」）。

## 5. 跨机协同的 UX

| 场景 | UX |
|---|---|
| 选择执行位置 | 会话/任务上标「在哪台设备跑」；可切换目标节点 |
| 附加远端 | 顶部显示「已连接到 <设备>」；连接状态指示 |
| 断线 | 显示「连接断开」，本地缓存只读；自动重连 |
| 审批 | 内嵌模态（`region.modal`）：动作摘要、影响、风险、批准/驳回 |
| 多外壳同看一会话 | 各自只读视图；命令经写者串行化 |

> **内嵌而非独立窗口**（ADR-0006）：一切弹层都在同一窗口内的图层里。

---

## 6. 离线 UX

- 离线时：本地会话照常可看、可用本地模型继续；远端节点相关操作标「离线不可用」。
- 恢复联网：后台同步，冲突/补传对用户<strong>尽量透明</strong>（v1 单写者，通常无冲突）。

---

## 7. 主题与可访问性

- **主题令牌**（`ui.theme`）：颜色/间距/字体是变量，插件与用户可换主题。
- 明暗、对比度、键盘可达性作为外壳职责统一处理（插件不各自为政）。

---

## 8. 反模式

- ❌ **外壳持有权威状态** → ✅ 状态从事件流派生（读模型）。
- ❌ **本机与跨机各写一套 UI 逻辑** → ✅ 同一「命令 + 事件」契约。
- ❌ **插件自建窗口 / 绕开宿主桥** → ✅ 内嵌 + 宿主桥（ADR-0006）。
- ❌ **每种端各做一套 UI** → ✅ 一套响应式 UI + 外壳重排。
- ❌ **外壳直接碰内核内部** → ✅ 只经契约（命令/事件）。
