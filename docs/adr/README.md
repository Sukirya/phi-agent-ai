# 架构决策记录（ADR）

> 状态：🌿 · 最后更新：2026-11-08

本目录存放 phi-agent 的架构决策记录。ADR 记录**难以逆转、且当时有真实取舍**的决定，让后来者知道「为什么是这样」。

---

## 什么时候写 ADR（三条门槛，缺一不写）

一个决定**同时**满足以下三条，才值得写 ADR：

1. **难逆**：改回去的成本很高（换语言、换同步模型、换插件 ABI）。
2. **反直觉**：没有上下文的人会问「为什么不那样做」。
3. **真有取舍**：当时确实有别的合理选项，且各有利弊。

三条缺一不写：

- 容易改的决定（选个配置项）：改了就是，不需要 ADR。
- 不反直觉的决定（显然这样做）：没人会问，不需要 ADR。
- 没有取舍的决定（只有一条路）：记录「我做了显然的事」没有价值。

> 门槛借鉴 `skills/docs/engineering/domain-modeling.md`。

---

## 格式

```
adr/
├── 0001-<slug>.md
├── 0002-<slug>.md
└── README.md   ← 本文件（含索引）
```

每份 ADR 一页以内，四段：

```markdown
# NNNN. <决定的一句话标题>

- 状态：提议 / 已接受 / 已废弃（被 NNNN 取代）
- 日期：YYYY-MM-DD
- 决策者：

## 背景
（什么问题逼出了这个决定？约束是什么？）

## 决定
（我们决定做什么。一句话说清。）

## 取舍
（选了 A，放弃了 B 和 C，各自代价是什么。为什么 A 的代价可接受。）

## 后果
（这个决定带来的影响、后续要注意的事、何时应该重新审视。）
```
