# 0009. 内核狭义化，能力由「发行基线 + 必需槽位」保证

- 状态：已接受
- 日期：2026-11-08
- 决策者：架构讨论

## 背景

文档里「内核」一词长期承担两种互不相容的含义：

- **机制派**（`principles.md` P1、`glossary.md`、ADR-0001、`module-map.md` §2）：内核只有总线/注册表/生命周期/基础端口，不含任何领域功能。
- **承载派**（`agent-loop.md` §0、`vision.md` §2、`model-gateway.md` §0/§5）：内核提供 Run/Step/检查点/预算，并强制预算与子 Agent 上限；`vision.md` 甚至写「策略 + 沙箱 + 审批 + 预算上限是内核级一等公民」。

两者直接冲突：一边要求 `kernel-*` 里不得出现 `Run/Session/Tool`，一边要求内核承载 Run 与预算。结果是 P10「移除任意模块」无法验收，且降级表允许「沙箱缺席 → 无隔离运行」「策略缺席 → 默认允许或拒绝」，与安全文档的默认拒绝相反。

真正的矛盾不是「内核该不该有职责」，而是**把两条不同的轴拧成了一个词**：

- **轴一 · 代码边界**：机制 vs 领域。
- **轴二 · 发行边界**：可缺席 vs 不可缺席。

## 决定

1. **内核只指狭义**：事件总线、服务注册表、生命周期、基础端口（时钟/ID/日志/配置）与**事件日志端口**。内核代码中不得出现领域词汇。`Run/Step/预算记账/策略求值/沙箱/模型网关` 全部在插件中。领域端口（`ModelPort`、`MemoryPort`、`SandboxPort` 等）定义在所属领域的契约包，不塞进内核。

2. **必需槽位（Required Slot）**：官方发行以配置声明哪些**能力契约**必须被某个实现占据（如 `policy.evaluate`、`sandbox.execute`、`model.invoke`）。**必需的是契约，不是具体插件**——实现可替换。

3. **发行基线（Release Baseline）**：官方发行必装的一组插件（运行时骨架、会话管理、策略、沙箱、审批、模型网关、持久化…）。基线插件**仍是普通插件**，走同一套扩展点 API，**不存在特权代码路径**；差别只写在发行清单里。

4. **运行模式（Run Mode）**替代「能启动/不能启动」的二元判断：

   | 模式 | 条件 | 行为 |
   |---|---|---|
   | `Normal` | 必需槽位齐备 | 全功能 |
   | `Degraded` | 运行中丢失安全组件 | 禁止发起新的副作用动作；只读与既有任务可见 |
   | `Maintenance` | 启动时必需槽位缺失 | 仅保留诊断、安装插件、修复配置入口 |

   必需槽位缺失**不拒绝进程启动**——否则用户连修复入口都没有。

5. **安全能力缺失一律拒绝，不降级为放行**：策略、沙箱、审批任一不可用 → 有副作用的动作 `deny`。显式豁免只能由用户作为独立管理操作给出，不能由模型、技能或待执行工具请求隐式触发。

6. **Null 实现必须诚实**：只读端口可以返回空集（「没有记忆」是合法状态）；写端口不得返回「成功」（假装写入成功 = 数据丢失）。

## 取舍

- **放弃**：「内核承载 Run 骨架」带来的直接性——Run 骨架现在必须经注册表从基线插件取。
- **放弃**：P10 原本「任意模块」的绝对表述——现在只对**可选模块**断言。这是承认现实：移除模型网关后不可能「一切照常」。
- **换来**：内核边界可静态检查（无领域词汇）；安全能力缺席时结构上无法放行；基线插件仍可被替换。
- **代价**：需要维护「必需槽位清单 + 运行模式」这一层配置；插件加载期要区分「可选缺失」与「必需缺失」。

## 后果

- `principles.md` P1/P10 改写：P10 只对可选模块断言；新增「安全能力缺失 → 拒绝」的不变式。
- `module-map.md` 降级表重写为「必需槽位缺席 → `Maintenance` / 基线缺席 → 明确降级或拒绝」；安全相关行不再出现「无隔离运行」。
- `agent-loop.md` §0、`vision.md` §2、`model-gateway.md` §0 的「内核」改指「运行时骨架（基线插件）」。
- `overview.md` 决策 5 的「待确认」状态废止；「跨语言边界只有一处」修正为两处（内核↔外壳、宿主↔QuickJS）。
- 需要一份「必需槽位清单」作为发行配置的一部分，随基线一起版本化。
