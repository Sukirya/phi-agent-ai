# 0004. 协同拓扑采用「对等节点」，服务器只是普通节点

- 状态：已接受
- 日期：2026-11-08
- 决策者：Sukirya

## 背景

多端协同（F3）需要一个拓扑假设：服务器是「必须的中继」还是「可选的对等节点」？这决定离线能力、身份信任模型，以及「本地优先」（P4）的成色。

## 决定

**任何两台设备（节点）都可以直接协同；服务端只是「一台常开的、能力可能更强的对等节点」，不是中心。** 没有服务端时，各节点独立运行；有服务端时，它参与协同的原因是「常开、适合做执行位置或换端目标」，而非「是协同的必经之路」。

v1 的协同形态是**单写者 + 附加（attach）**：会话归属一个节点，其他端附加查看与控制。跨公网直连所需的 NAT 穿透，属于 `50-distributed/` 的实现问题，不改变「对等」这一模型。

## 取舍

- 选 A（对等节点）：最贴合本地优先与「每端都能单独运行」；无单点失败。代价是跨公网连接更复杂（NAT 穿透/连接建立）。
- 弃 B（服务器中继）：实现最简单（NAT 统一解决），但服务器成为事实中心，弱化本地优先，且离线/独立运行能力受损。
- 弃 C（混合）：局域网直连 + 跨网中继最实用，但实现最复杂；**因 v1 不要求跨公网协同，暂不选**。C 可作为 R2 阶段的演进（不推翻 A 的对等模型，只是给跨网加中继适配器）。

## 后果

- 身份与信任是**节点对节点**显式建立的（上下文①），不依赖中心权威。
- 「协同」在架构上 = 外壳附加到别的节点，或把 Run 所有权转给别的节点；没有「必须在线」的角色。
- 跨公网协同的能力在 v1 可以受限（同机/同局域网优先），并在 `50-distributed/topology-and-sync.md` 明确标注边界。
