# 0010. 安全权威只能收紧；审批绑定冻结后的具体动作

- 状态：已接受
- 日期：2026-11-08
- 决策者：架构讨论

## 背景

三个问题叠在一起，任何一个单独修都不够：

1. **安全规则可被插件扩展，却没有规定谁有权改它们。** `content.policyRule`、`judge.policyEvaluator`、`judge.approver`、`provider.sandbox`、`mw.beforePolicyDecision` 全是扩展点；插件与内置走同一套 API（没有「亲儿子特权」）；规则又按最高 `priority` 生效。结果：第三方插件可以提交一条更高优先级的 `allow` 规则来覆盖用户限制。
2. **审批没有绑定到「实际执行的那一次动作」。** `ApprovalRequest` 只含 `invocationId`；中间件 `mw.beforeToolInvoke` 可以在批准之后改参数；权限撤销、审批过期、资源变化都不触发复核。用户批准了 A，执行的可能是 B。
3. **工具自报的 `sideEffect` 被赋予过高信任。** 第三方工具/MCP Server 可以把危险操作声明为 `none`；「工作区写文件有 diff 所以可逆」既没备份也没回滚条件；读取凭据没有写副作用，但显然不是低风险。

## 决定

### 1. 安全权威：层内排序，跨层取交集

- **最终允许范围 = 宿主能力 ∩ 用户授权 ∩ 当前有效策略。**
- `priority` **只在层内**决定规则命中顺序；**跨层不取「最高优先级者胜」**，而是取交集。任何一层拒绝，最终就是拒绝。
- 普通插件贡献的规则与中间件**只能收紧，不能放宽**：不允许把 `deny/ask` 改成 `allow`，不允许把自己的能力范围扩大。
- `modify` 同样只能收紧。
- **利益冲突规则**：提供某工具的插件，不得贡献审批该工具的审批者实现。
- 用户**可以**修改默认规则，或显式信任并替换策略/沙箱/审批实现——但这属于**独立的管理操作**，不能由模型、技能、待执行工具请求隐式完成。替换后的实现仍不能绕过宿主能力校验、预算与审计入口。

### 2. 审批绑定不可变动作摘要

审批对象（`ApprovalRequest` 必含）至少包括：

| 项 | 说明 |
|---|---|
| 执行主体 | 由宿主附加的 `Principal`（用户/项目/Agent/Run 组合），不可由调用方伪造 |
| 目标节点 | 动作将在哪个节点执行 |
| 工作区 / 资源身份 | 规范化路径 + 内容哈希；平台支持时用文件 ID/句柄，平台不支持才退化为路径 + 哈希 |
| 工具及实现版本 | `toolId@version` + provider 版本 |
| 规范化参数 | 排序、去重、路径归一后的参数摘要 |
| 命令行为相关项 | 执行命令时的 cwd、环境变量白名单、stdin 摘要 |

规则：

- **参数或目标变化 → 旧审批失效**，重新跑策略；需要人工时重新审批。
- **执行前复核**：权限是否撤销、审批是否过期、实际资源是否与批准时一致。
- **路径字符串的摘要不能替代真实资源校验**——执行前重新解析并比对资源身份，不长期持有句柄（审批窗口可达 30 分钟，句柄在多数平台撑不住）。

### 3. 风险画像：四维，声明只作输入

工具声明的 `sideEffect` **保留，但降级为输入**。最终风险由**受信执行层**结合能力与资源判定：

```
effectiveRisk = max(工具声明的, 宿主评估的)
```

四个维度**不可压成一个「是否可逆」**：

| 维度 | 例 |
|---|---|
| **数据修改** | 写/删/覆盖；`reversible` 只是这一维的属性，且需要旧内容保存 + 回滚条件才成立 |
| **信息读取与外发** | 读工作区（低）/ 读凭据（高）/ 发网络（高） |
| **费用** | 模型调用、付费 API、云资源 |
| **代码执行与权限** | 执行命令、加载原生库、申请新能力 |

第三方工具与远端 MCP **行为未知，按保守等级处理**：未声明的维度不得视为无风险。

## 取舍

- **放弃**：插件自由定义「我的动作很安全」的信任模型；也放弃「一条高优先级规则就能全局覆盖」的简单性。
- **放弃**：审批一次、长期有效的便利。改参会触发二次审批。
- **换来**：用户批准的内容与最终执行的内容可对应；插件无法靠自报或高优先级绕过限制；保留用户主动替换整个安全实现的能力。
- **代价**：策略求值从「排序取第一」变成「分层求交集」，实现更复杂；审批记录体积变大（要存动作摘要与资源身份）。

## 后果

- `policy-and-approval.md` §3.2 与 §5 改写；`I-6-1`（冲突按优先级）、新增 `I-6-5`（审批绑定摘要）。
- `domain-model.md` §6.3 `ApprovalRequest` 增加动作摘要字段；`ToolDefinition.sideEffect` 注释改为「声明，非判决」。
- `plugin-system.md` 扩展点表标注信任级别：安全相关扩展点只能收紧。
- **主体 Principal** 成为跨上下文统一概念：策略判定的 subject、事件订阅过滤、记忆读写校验、UI 宿主桥鉴权，全部以宿主附加的 Principal 为准。
- `#31`（秘密）与 `#30`（来源污点）在此之上补：读取凭据进入「信息读取与外发」维度；外部内容带信任等级，摘要与记忆写入必须保留来源。
