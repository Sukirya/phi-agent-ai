# 0011. 换端以整个 Session 为所有权单位

- 状态：已接受
- 日期：2026-11-08
- 决策者：架构讨论

## 背景

换端文档此前允许多种粒度并存：

- `Session.ownerNodeId` 被定义为**唯一写者**，`I-2-1` 说「同一时刻 Session 的写者唯一」。
- `handoff.md` 却说「Run 可独立转移，不牵连整个会话」，且「转移单位可以是 Run，也可以是整个 Task」。

两者同时成立会得到无法回答的状态：一个 Session 仍属 A，其中部分 Run 已移到 B——谁有权往这个 Session 追加事件？日志的 seq 归谁排？

## 决定

**R1 首版以整个 Session 为所有权与交接单位。**

1. Session 是唯一写者的单位；其进行中的 Run 与全部子 Run **随它一起交接**。
2. 用户从某个 Run 发起换端时，界面必须说明「将移动所属会话的执行位置」，而不是暗示只移动这一次运行。
3. **Task 是跨会话的目标与组织单位**；「把 Task 指派给某节点」表示组织与协作，**不等于**原子搬迁它关联的所有 Session。
4. 首版**不承诺**跨多个 Session 的整体原子转移。
5. 交接必须先到达**安全暂停点**：补齐最终事件与所需资源（Blob、工具版本、工作目录等），再提交。
6. **提交结果不确定时暂停并核对持久决策**；旧节点不得自行恢复执行。

## 取舍

- **放弃**：同一 Session 内一部分 Run 留在 A、另一部分搬到 B 的灵活性。
- **放弃**：Task 级别的原子搬迁（留给 R3 团队场景再议）。
- **换来**：日志顺序与所有权规则唯一且可验证；一条 Session 日志只有一个写者，换端就是换 owner 并复制一份完整日志。
- **代价**：交接搬运的数据量更大（整个会话的历史与检查点）；用户界面上「换端」必须解释为会话级操作。

## 后果

- `handoff.md` §1/§3 改写；`domain-model.md` `I-2-1` 明确为「Session 为换端单位」。
- **#15（事件流身份与排序）随之消解**：同步单元 = 会话日志，信封携带 `sessionId + aggregateId + aggregateVersion`；单调钟不再承担持久排序职责，只用于进程内超时与耗时测量。
- `local-first.md` §3 补「聚合版本」概念；`topology-and-sync.md` §6 信封补字段。
- R1 准入条件需写明：安全暂停点定义、尾部事件补齐、持久化提交决策、旧写者失效确认。
