## 0. 一句话

**别拿成熟期的图去套 MVP。** 但地基（微内核、事件溯源、端口、能力安全）从 MVP 就要立住——它们是「可移除性」的前提，后补代价极高。功能则按「桌面 → 服务端 → 移动」逐段加。

---

## 1. 交付边界（MVP / v1 / 后续）

> 回应「阶段没有清晰交付边界」。核心原则：**先证明用户能完成一次真实编码任务**，再谈广度。

| 阶段 | 必须证明什么 |
|---|---|
| **MVP** | 桌面端完成 **「读取仓库 → 修改文件 → 运行验证 → 展示结果」**；同时具备人工审批、预算（调用前预留）、取消、持久化，以及**安全恢复或停下来核对未知结果**的能力 |
| **v1** | 桌面 + **无头服务端**、局域网 attach、**可安装的基础 TS 插件**、基础记忆——让「可扩展」与「多设备」真正可用 |
| **后续迭代** | 多 Agent 先做**单层主从**；再扩展辅助模型审批、完整移动体验、换端 R1、复制 R2、插件市场 |

**据此调整**：
- **移动端完整支持不作为 v1 门槛**。
- **F4 多 Agent / 辅助模型审批从 v1 硬门槛移到后续迭代**；但**架构预留必须在 v1 就位**（执行树 `parentRunId`、`strategy.orchestration` 扩展点、Task 树、深度/扇出上限、取消传播）。
- **移动技术验证提前**：在**冻结插件 ABI 之前**，验证 Rust + QuickJS 在移动端的启动、宿主调用、挂起与恢复限制。完整移动产品可以后做，但平台假设不能到最后才发现不成立。

| 阶段 | 架构长什么样 | 功能范围 | 该操心什么 |
|---|---|---|---|
| **MVP** | 单进程节点：Rust 内核 + 内置外壳 + 发行基线插件；无同步；事件日志只落本地 | 基础 Agent 能力（循环/工具/技能）+ 插件骨架 + 一次真实编码任务 | 内核边界是否真干净（无领域词汇）；必需槽位/运行模式是否成立；P10 冒烟是否跑通；预算/策略/恢复是否已在 |
| **v1** | 内核与插件分离为独立制品；TS 插件 ABI（内嵌 QuickJS）上线；服务端节点可用；局域网 attach | 插件可安装、基础记忆、多设备 | 插件 API 版本化；跨端一致性；成本与限额；确定性测试进 CI |
| **成熟期** | 多层插件（声明式/TS/原生+自带 CLI）；换端 R1、状态复制 R2、团队节点 R3；插件市场 | 完整生态、多 Agent | 安全边界；向后兼容；多租户；持续评测 |

## 2. MVP（桌面优先）

### 2.1 必须立住的地基（不可推迟）

| 地基 | 为什么不能推迟 |
|---|---|
| 内核狭义边界（**内核无领域词汇**）+ 发行基线/必需槽位 | 后补会把内核做胖，P1/P8/P10 同时失败（ADR-0009） |
| 端口 + **诚实的** Null 实现 | 没有它，可移除性无法测试；写端口「假装成功」会静默丢数据 |
| 事件日志（会话/运行主线）+ 聚合版本 | 后补换端/回放/复制的代价极高 |
| 预算三重上限 + **调用前预留** | 「调用后扣费」保证不了硬上限，后补意味着先放任烧钱 |
| 策略 + 审批（至少 human + 默认拒绝 + **只能收紧**） | 后补意味着先放任越权 |
| 插件清单 + 能力声明 + **安全扩展点信任级** | 后补意味着先建立「无约束」的插件生态 |
| **取消传播 + 结果未知待核对** | 恢复语义错了，用户会发现「任务没停但电脑在动」 |

### 2.2 可以先用简版

- 模型网关：先接 1 个 provider，路由写死；后补多 provider 与降级链。
- 记忆：先 SQLite 事实表 + BM25（甚至先无向量）；后补双通道与重排。**但 `forget` 与脱敏从 MVP 就要有**——删除是承诺，不是后补项。
- 多 Agent：先单 Agent；架构预留（执行树/编排扩展点）就位，实现后加。
- 协同：先同机 attach；局域网后补。
- UI 扩展：先声明式（D 档）；C 档后补。
- 插件分发：先本地目录；市场后补。

### 2.3 MVP 验收

```
【功能】桌面端完成一次真实编码任务：读仓库 → 改文件 → 跑验证 → 展示结果
        且覆盖：人工审批、预算超限即停、用户取消、重启后恢复

【可移除性】对每个「可选」插件：禁用 → 启动 → 关键用例
           对每个「必需槽位」：移除 → 进入 Maintenance / Degraded
           写端口 Null 不返回成功

【安全】默认拒绝生效；辅助模型不能批高风险；审批绑定动作摘要（改参即失效）
【恢复】崩溃注入后：不重复副作用；结果未知 → 待核对，不自动重试
```

## 3. v1（服务端 → 移动验证）

按 Q3 顺序：

| 步骤 | 目标 | 验证什么 |
|---|---|---|
| 1. 桌面稳定 | 内核/插件边界、循环、策略、记忆 | 可移除性、功能地基、一次真实编码任务 |
| 2. 服务端节点 | 常驻、无头、跨机 attach | 对等拓扑、传输、跨端一致性 |
| 3. **移动端技术验证** | Rust + QuickJS 在移动端的启动/宿主调用/挂起恢复 | **平台假设**（在冻结插件 ABI **之前**做） |

**v1 的架构动作**：
- 插件制品化（内核与插件独立分发、版本化）+ **插件可安装**（本地目录）。
- TS 插件 ABI 上线（内嵌 QuickJS）+ iframe/引擎的 UI 隔离。
- **确定性测试进 CI**（安全/预算/恢复/卸载），能力评测在成长期起阻塞。
- 成本治理（路由 + 缓存 + 预留）。
- 基础记忆（含 `forget` 与脱敏）。

## 4. 成熟（预留能力逐个落地）

| 预留 | 触发信号 | 依赖 |
|---|---|---|
| **R1 换端继续** | 用户要跨设备续跑 | 事件日志 + 检查点 + 对等传输（已具备） |
| **R2 状态复制** | 用户要多端同时编辑 | 分区 + 逻辑单写（`local-first.md` §5） |
| **R2 跨公网** | 用户要远程协同 | 中继/穿透适配器（不改对等模型） |
| **R3 团队节点** | 多用户共用一个服务器节点 | 身份/信任 + 多租户边界 |
| **插件市场** | 第三方插件生态形成 | 签名/来源验证 + 版本协商 |

> 每个预留都**不需要推翻已有设计**——这正是把它们列为「预留」而非「另起炉灶」的原因。

## 5. 演进触发信号（何时动架构）

| 信号 | 动作 |
|---|---|
| P10 冒烟开始失败 | 先修解耦，不加功能 |
| 内核 API 数量超标 | ADR：拒绝或合并 |
| 内核出现领域词汇 | 立即移出（P1） |
| 必需槽位清单不断膨胀 | 重新划分基线，或拆分契约 |
| 单写者成瓶颈 | 启 R2 |
| 跨公网需求明确 | 启 R2 中继 |
| 任务被设备绑死 | 启 R1 |
| 成本频繁触顶 | 强路由/缓存/压缩 + 检查预留 |
| 检索 recall 下滑 | 查检索/嵌入/准入 |

> 原则：**先让测试变绿，再加功能**。可移除性一旦破了，后面每加一个功能都是负债。

## 6. 里程碑（示意，待排期）

```
   M0  地基：内核（狭义）+ 机制端口 + 诚实的 Null + 事件日志 + 预算预留 + 策略（human）
   M1  基础 Agent：循环 + 工具 + 技能 + 单 provider（桌面）
   M2  插件骨架：清单(含 part) + 注册 + 懒激活 + P10 冒烟 + 运行模式
   M2.5 MVP 验收：桌面完成一次真实编码任务（读仓库→改文件→跑验证→展示）
   M3  记忆 MVP：SQLite 事实表 + BM25 + 准入 + forget/脱敏 + golden 集
   M3.5 移动技术验证（在冻结插件 ABI 之前）
   M4  v1 服务端节点 + 同机/局域网 attach
   M5  TS 插件 ABI（内嵌 QuickJS）+ 自带 CLI 逃生舱 + 插件可安装
   M6  多 Agent 单层主从 + 辅助模型审批（后续迭代）
   M7  移动端完整体验
   M8  R1 换端 → R2 复制 → 插件市场（按需）
```
