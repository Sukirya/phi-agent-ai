---

## 0. 一句话

**Agent 是非确定性的：同一任务两次运行路径可能不同。所以「够好」不能靠直觉，要靠**评测集进 CI**——改提示、换模型、改工具、调检索之前，先跑评测，分数掉了不许上线。**

---

## 1. 为什么评测是一等公民

- **非确定性**：不能用「同输入同输出」的断言，只能用品质量指标 + 门槛。
- **静默退化**：不评测，质量会在某次改动后悄悄下降而无人察觉（`agent-research` 反复警告）。
- **可信来源**：厂商自报基准口径不一、互相争议，**必须在自有数据上实测**。

---

## 2. 评测集（从第一天起）

> `agent-research` 的硬建议：**从第一天建 golden 评估集**（100–200 条）。

| 评测集 | 评什么 | 例 |
|---|---|---|
| **能力评测** | 任务成功率（端到端） | 给定仓库，修复一个失败测试 |
| **检索/记忆评测** | recall@k、命中率、噪声率 | 给定查询，应召回哪些事实 |
| **权限/安全评测** | 越权是否被挡、审批是否正确 | 注入攻击对照用例 |
| **工具评测** | 工具选择是否正确、参数是否合法 | 该调哪个工具 |
| **成本/步数** | 在预算内完成的比率 | 同任务的步数/成本分布 |

每条评测 = **输入 + 期望要点**（不要求逐字匹配，用规则 + LLM-as-judge）。

### 2.1 确定性测试与故障注入（硬约束）

> 越权、预算、恢复、卸载这类是**硬约束**：答案是确定性的（放行/拒绝、超限/未超限），**不能用任务成功率或 LLM judge 判定**。

| 确定性测试 | 断言什么 |
|---|---|
| 权限/安全 | 越权发生率 **= 0（硬门禁）**；默认拒绝；辅助模型不能批高风险 |
| 预算 | 调用前预留；额度不足拒绝发起；并发记账不超限 |
| 恢复 | 崩溃注入（执行成功后记录前、记录后执行前）；结果未知进入待核对、不自动重试 |
| 插件卸载 | 在途调用处理；卸载后无残留；进程内原生插件不可热卸载 |
| 换端（R1） | 安全暂停点；提交不确定时暂停核对；不双写 |

## 3. 进 CI（门禁）

```
   改动（提示/模型/工具/检索/策略）
        │
        ▼
   跑评测集 ──▶ 指标对比基线 ──┬─ 达标 ──▶ 允许合并
                              └─ 退化 ──▶ 阻断（或需显式豁免）
```

- **基线**：每个评测集有当前基线分数；低于基线一定幅度即失败。
- **广度 + 深度**：既有「广覆盖」的浅任务，也有「深链路」的难任务（`agent-research` 建议）。
- **成本也评**：同任务的平均步数/成本是评测指标之一。

**分阶段进 CI**（回应「从第一天评测 vs 成长期才进 CI」的矛盾）：

| 阶段 | 进 CI 的评测 | 阻塞？ |
|---|---|---|
| **MVP 起进 CI** | 确定性测试（安全 / 预算 / 恢复 / 卸载，§2.1） | ✅ 硬约束，每次必跑 |
| **MVP 起维护但不阻塞** | 记忆 / 检索 golden 集 | ⛔ 先积累基线，不阻塞合并 |
| **成长期起阻塞** | 能力评测、成本评测 | ✅（需稳定的多 provider 与任务集） |

> 「从第一天」指的是 **golden 集与确定性测试**，**不是全部评测门禁**。确定性测试是硬约束，必须从第一天起每次跑；能力/成本评测依赖稳定的多 provider 与任务集，成长期才具备阻塞条件。

---

## 4. 指标与门槛

| 维度 | 指标 | 门槛（示意，待标定） |
|---|---|---|
| 任务 | 成功率 | ≥ 基线 |
| 检索 | recall@k | ≥ 基线；不得低于上次 |
| 安全 | 越权发生率 | = 0（硬门禁） |
| 成本 | 平均步数/成本 | ≤ 基线 × 容差 |
| 稳定 | 同任务多次运行的方差 | 在容差内 |

**安全类指标是硬门禁**：越权必须为 0，不接受「略降」。

**可复现性参数**（否则分数漂移无从归因）：

- **重复**：每个随机评测任务重复 **N 次**（建议 N ≥ 3），取**中位数**（不是单次）。
- **基线与容差**：基线是**滚动值**；容差**显式定义**（绝对或百分比），不用「差不多」。
- **环境隔离**：固定模型版本、固定提示、隔离工作区、禁用网络或固定 mock。
- **不稳定用例**：显式**标记**，不静默忽略。

---

## 5. 评测与记忆的关系

- 记忆/检索评测是**独立的评测集**（不混进任务评测），便于定位退化来源。
- 改**嵌入模型 / 检索策略 / 准入规则**前，先跑检索评测。
- 检索结果的 **Receipt**（来源/时间/置信度）是评测可核对的对象。

---

## 6. 反模式

- ❌ **只看直觉不建评测集** → ✅ golden set 进 CI。
- ❌ **拿厂商基准当结论** → ✅ 自有数据实测。
- ❌ **安全只做「尽量」** → ✅ 安全类硬门禁（越权=0）。
- ❌ **只评质量不评成本** → ✅ 成本/步数也是指标。
- ❌ **改检索不跑检索评测** → ✅ 独立评测集 + 先跑后改。
- ❌ **用 LLM judge 判权限/预算/恢复这类硬约束** → ✅ 确定性测试断言（越权=0 等，§2.1）。
- ❌ **评测环境不稳定导致分数漂移** → ✅ 固定模型版本/提示/工作区，禁网或固定 mock。
- ❌ **只跑一次就下结论** → ✅ 重复 N 次取中位数。
