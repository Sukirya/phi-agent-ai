## A. 架构走向的四个问题（已决定 2026-11-08）

### Q1 · 协同拓扑 → **已定：对等节点**（ADR-0004）

任何两台设备可直连协同；服务端只是「一台常开的、能力更强的对等节点」，不是协同的必经之路。v1 协同 = 单写者 + attach。跨公网 NAT 穿透是 `50-distributed/` 的实现问题，v1 可受限（同机/同网优先）。

### Q2 · 内核语言/运行时 → **已定：Rust 内核 + TS 外壳**（ADR-0003）

一套 Rust 内核经 Tauri 2 覆盖桌面+移动，服务端是同内核原生二进制；UI 用 Solid（TS），跨语言边界收敛到「命令契约 + 事件流契约」一处；插件以 TypeScript 为主（内嵌 JS 引擎），性能敏感处自带原生 CLI（ADR-0005）。

### Q3 · v1 优先端 → **已定：桌面优先**

顺序：**桌面 → 服务端 → 移动**。桌面先验证内核与插件边界；服务端验证常驻与跨机；移动验证可移植性。触达 `80-roadmap/evolution.md` 与 P10 冒烟覆盖顺序。

### Q4 · 默认形态 → **已定：编码 Agent 优先**

首批内置工具/技能偏代码/仓库/终端，参考 Claude Code / OpenCode。**这不影响架构**（架构领域无关），只影响首批插件与示例。

## B. 领域划分（**Q5/Q6/Q7 已定 2026-11-08**）

### Q6 · 「记忆/反思」→ **已定：升格为核心域**

**决定**：把上下文 ⑩ 从支撑域升格为**核心域**，并更名为「**认知、记忆与反思**」。
**理由**：跨会话记忆与「反思/整理」（dreaming 式沉淀）不是「把数据存好」这类支撑功能，而是**产品差异点**——它决定 Agent 是否越用越懂你/你的项目。它值得独立演进节奏、独立评测集、独立优先级。
**影响**：`20-domain/context-map.md` 已更新（⑩ 标 ★）；`40-runtime/context-and-memory.md` 的记忆/反思获得更高优先级；`80-roadmap` 中记忆从「MVP 简版」提前。

### Q7 · 「治理」为何独立成上下文？ —— **解释（保持独立）**

**它是什么**：治理上下文（⑥）拥有一个**只属于它自己的语言**：`Policy`（规则）、`Decision`（判定）、`Approver`（审批者）、`Capability`（能力令牌）、`ApprovalRequest`（审批请求）。这些词不属于「Agent 运行时」——运行时管的是「怎么想、怎么调工具」，治理管的是「**这事能不能做**」。

**为什么不能并进 Agent 运行时**——用 DDD 的判据「**语言边界 = 变更理由边界**」看：

| 维度 | Agent 运行时 ③ | 治理 ⑥ |
|---|---|---|
| 核心问题 | 任务怎么完成 | 这件事该不该被允许 |
| 变更驱动 | 模型能力、循环策略、工具 | **威胁模型、合规、风险偏好** |
| 变更节奏 | 跟随产品功能 | 跟随安全事件，独立且可能很急 |
| 测试方式 | 功能/能力评测 | **安全对抗用例**（越权必须=0） |
| 谁调用它 | —— | 它**横切**多个上下文：工具调用、模型调用、记忆写入、插件激活都问它 |

**关键论点**：治理不是「运行时的一部分」，而是**横切多个上下文的单一收口**。工具、模型、记忆、插件都要过它——如果它藏在运行时里，其他上下文就得绕过边界去调运行时，边界立刻被污染。

**结论**：保持独立上下文，作为**支撑域**（必不可少、但不是产品差异点）。它的热路径校验是**唯一收口**，这也是审计可追溯的根。

**反例**：把策略判定散落进每个工具内部 → 无法回答「谁在何时、依据哪条规则批准了什么」→ 审计失效。

### Q5 · 「会话」与「任务」是否分开？ → **已定：B-lite（引入可选 Task）**

**现状**：`Session → Turn → Run → Step`，任务被并进 Run（一次执行）。提出三种取向：

| 取向 | 模型 | 优点 | 缺点 |
|---|---|---|---|
| **A · 无 Task** | 只有 Session（交互上下文）+ Run（一次执行）；「任务」是若干 Run 的语义组合 | 最简；「一次对话解决一个目标」天然成立 | 表达不了**跨多次会话**的长期目标；没有可指派的单位 |
| **B · Task 独立** | 新增 `Task`（命名目标，独立生命周期，可跨会话、可指派、可协作），拥有多个 Run | 支撑长期目标、多 Agent 协作、多端指派、团队看板（R3） | 多一层实体与关联，对「随口一问」是过度设计；命名易与 Session 混淆 |
| **C · Task = Run** | 现状 | 无改动 | 单位太细（一次循环），当不了「目标」 |

**按本项目需求的判据**：

- 「一次对话解决一个目标」→ A 够用。
- 「今天问一点、明天接着做同一个目标」→ **A 不够**，需要跨会话的容器 → B。
- 「把任务派给某台设备 / 某个人」→ 需要**可指派的单位**；Run 太技术，Session 太宽 → B。
- 「多 Agent 协作一个目标」→ 父目标 + 各 Agent 的子 Run 更自然 → B（Task 树）。
- 「团队共享节点/看板」（R3）→ 几乎必然需要 Task。

**推荐：B-lite（轻量引入 Task）**

```
   Task（可选 / 可选长生命周期 / 可指派）
     ├── 关联 0..*  Session（交互上下文；通常 1 个主会话）
     └── 拥有 0..*  Run（一次执行；Run 必须携带 taskId）
```

- **Session** 保持「交互上下文」（对话，含 Turn）——**不变**。
- **Run** 保持「一次执行」——**不变**。
- **Task** 是**新增的可选顶层**：一个命名目标。随手一问 → 隐式 Task（或直接用 Session 即任务）；跨会话/要指派/要协作 → 显式 Task。
- **为什么 B-lite 而不是全量 B**：不让「随口一问」也套上 Task 的仪式；用得上才用。
- **为什么不是纯 A**：本项目明确要「多端协同 + 多 Agent 协作 + 预留团队」，这三者都需要「目标」这个单位，缺了它，R1/R3 会被迫事后硬塞。

**扩展性角度**：Task 只是**多一层可选聚合**，不触碰内核；用不上就不加（P10）。若采纳，我会把它加进 `20-domain/domain-model.md`（新聚合 + 事件），并更新 `context-map.md` 的 ② 上下文。

> **已定（2026-11-08）**：采纳 **B-lite**。已落 ADR-0008；`20-domain/domain-model.md` 新增 Task 聚合（3.0）与事件；`context-map.md` ② 更名为「会话、任务与运行」；`glossary.md` 增补 Task。
> **修订（2026-11-08，见 Q18）**：「可选」只指**界面可隐式**；**数据上恒在**——每个 Run 必带 `taskId`，Task 拥有 `0..*` Run，无全局默认 Task（惰性创建隐藏 Task）。

## B′. 内核边界与安全权威（**已决定 2026-11-08**）

> 来源：一次对全套文档的评审（36 条），核实后 25 条属实、11 条部分属实。以下为对应的决定，已落 ADR-0009～0011 与各子系统文档。

### Q14 · 内核是一个东西，还是两个概念？ → **已定：内核狭义化 + 发行基线**（ADR-0009）

「内核」此前同时承担「机制层」与「承载 Run/预算」两种含义（六份文档 vs 三份文档对撞）。决定：

- **内核只指狭义**（事件总线/注册表/生命周期/机制性端口），**无领域词汇**；`Run/Step/预算/策略/沙箱/模型网关` 全在插件。
- **发行基线**：官方必装的插件组，仍是普通插件、实现可替换、**无特权代码路径**。
- **必需槽位**：必须被某实现占据的**能力契约**；缺失 → `Maintenance`（**不拒绝进程启动**）。
- **运行中丢失安全组件** → `Degraded`，**拒绝发起新的副作用动作**。
- **安全能力缺失一律拒绝，不降级为放行**；**Null 实现必须诚实**（写端口不得假装成功）。
- **P10 只对可选模块断言**：不是「任何模块删掉都照常」。

### Q15 · 谁有权改安全规则？ → **已定：普通插件只能收紧**（ADR-0010）

- **最终允许范围 = 宿主能力 ∩ 用户授权 ∩ 当前有效策略**；`priority` 只在**层内**排序，跨层**取交集**。
- 用户可显式信任并**替换**安全实现，但这是**独立的管理操作**，不能由模型/技能/工具请求隐式触发。
- **利益冲突**：提供某工具的插件不得审批该工具。

### Q16 · 审批绑什么？ → **已定：绑定冻结的动作摘要**（ADR-0010）

`ActionDigest`（主体/节点/资源身份/`toolId@version`/规范化参数/命令相关项）；参数或目标变化 → 审批失效；执行前复核权限与资源；**路径字符串摘要不能替代真实资源校验**。

### Q17 · 风险怎么判？ → **已定：四维画像，声明只作输入**（ADR-0010）

数据修改 / 信息读取与外发 / 费用 / 代码执行与权限；`sideEffect` 降级为声明；`effectiveRisk = max(声明, 宿主评估)`；**第三方与远端 MCP 按保守等级处理**。

### Q18 · Task 可选到什么程度？ → **已定：数据恒在，界面可隐式**（ADR-0008 修订）

每个 Run 必须有 `taskId`；Task 拥有 `0..*` Run；**不使用全局默认 Task**，在首个 Run 被调度时惰性创建隐藏 Task；模型不得静默合并任务。

### Q19 · 多 Agent 与 Turn 不变量冲突 → **已定：根 Run 唯一**（`I-3-5`/`I-3-6`）

同一 Turn 至多一个活跃**根 Run**；子 Run 经 `parentRunId` 组成执行树，不新建用户轮次；根 Run 终态后有界宽限期内**强制取消全部后代**；子 Agent 默认只读工作区。**实现退到后续迭代，架构预留 v1 就位。**

### Q20 · 换端的单位 → **已定：整个 Session**（ADR-0011）

Session 是唯一写者与同步单位；Run 与 Task 不单独转移；首版不承诺跨多 Session 的原子转移。**顺带消解**了「聚合独立日志 vs 只按 sessionId 排序」的不一致。

### Q21 · 隐私承诺怎么落到链路？ → **已定：外发授权 EgressGrant**

「默认不上传」指**存储**；**外发**按接收方/用途/内容类别分别授权（主模型、辅助审批、嵌入、摘要各自）；**降级只能在已授权服务集内**；提供「仅本地」模式。
