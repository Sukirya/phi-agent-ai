# 术语表 / 领域语言

> 状态：🌱（随讨论增补） · 最后更新：2026-11-08

这是 phi-agent 的**统一语言（ubiquitous language）**。所有设计文档与代码中的专有名词以本表为准。

**规则**（借鉴 `skills` 的 `domain-modeling`）：

- 只放**术语**——一个词「是什么」，一两句话，附上**被放弃的同义词**（列在 `_避免_` 下）。
- 不放实现细节、不放决策、不放临时笔记。
- 引入新词先改本表，再在文中使用。同一个概念只允许一个正式词。
- 本表会**变短也会变长**——术语被合并或废弃是正常的。

---

## A. 运行时与部署

| 术语 | 定义 | _避免_ |
|---|---|---|
| **节点 Node** | 一个运行着内核 + 一组插件的进程实例。有稳定身份、能力清单与地址。桌面/移动/服务端都是节点。 | 实例、instance、端 |
| **内核 Kernel** | 节点中最小且稳定的**机制层**：事件总线、注册表、生命周期、机制性端口（存储/事件日志、传输、时钟、ID、日志、配置）。**不含任何领域功能**——`Run/Session/Tool` 等词不得出现在内核代码里。 | 核心、core、引擎、广义内核（**不设此说法**） |
| **发行基线 Release Baseline** | 官方发行**必装**的一组插件（运行时骨架、会话、策略、沙箱、审批、模型网关、持久化…）。仍是普通插件：同一套扩展点 API，**无特权代码路径**，实现可替换。 | 内置模块、core plugins |
| **必需槽位 Required Slot** | 一个**能力契约**的位置，必须被某个实现占据（如 `policy.evaluate`、`sandbox.execute`）。必需的是契约，不是具体插件。 | 必装插件、强制模块 |
| **运行模式 Run Mode** | 节点因依赖状态的差异而处的模式：`Normal`（齐备）/ `Degraded`（丢失安全组件，禁止新副作用）/ `Maintenance`（启动时缺必需槽位，仅诊断与修复）。 | 启动失败、健康状态 |
| **外壳 Shell / 前端 Frontend** | 附加到节点、用来看/控会话的 UI。可以同机（进程内）或跨机（经传输）。 | 客户端、client、GUI |
| **适配器 Adapter** | 某个端口的实现，吸收平台差异（SQLite、WebSocket、模型 API…）。 | 实现、impl、驱动 |
| **插件 Plugin** | 注册进内核、扩展系统能力的可加载单元。有清单、生命周期、声明的能力。 | 扩展、extension、mod、模块 |

## B. 协同与分布式

| 术语 | 定义 | _避免_ |
|---|---|---|
| **会话 Session** | 一段有边界的交互上下文（对话）。默认由**一个节点**持有（单写者）。包含轮次、消息、记忆作用域与运行。 | 对话、聊天、线程 |
| **任务 Task** | 一个**命名的目标**，可跨会话、可指派、可由多个 Run/Agent 协作。**数据上恒在**（每个 Run 必带 `taskId`），**界面上可隐式**（未显式建立时惰性创建隐藏 Task，无全局默认 Task）。 | job、to-do、工单 |
| **轮次 Turn** | 会话中一次「用户发言 + Agent 全部回应」的往返。 | 消息、message |
| **运行 Run** | 会话内一次 Agent 行动循环的执行，产出若干步骤与检查点。 | 任务执行、job、execution |
| **步骤 Step** | 运行中的一次循环迭代（一次「规划→行动→观察」）。 | 迭代、iteration |
| **执行树 Run Tree** | 根 Run 与子 Run 经 `parentRunId` 组成的树；一个 Turn 至多一个活跃**根 Run**，子 Run 并行但不新建用户轮次。 | 子任务、subagent 树 |
| **结果未知 Outcome Unknown** | 工具调用的一种终态：可能已执行、但无法查证且非幂等。暂停依赖它的后续动作，等待核对。 | 失败、超时（都不准确） |
| **附加 Attach** | 一个外壳连到某节点的某会话，进行查看/控制（v1 协同的基本形态）。 | 连接、connect |
| **换端 Handoff** | 把进行中 Run 的所有权（检查点 + 事件）迁到另一节点继续（预留 R1）。 | 迁移、migration、转移 |
| **日志 Journal** | 某个聚合的事件追加日志，是可回放、可复制的事实源。 | 事件流、log |

## C. Agent 运行时

| 术语 | 定义 | _避免_ |
|---|---|---|
| **Agent 定义 Agent Definition** | 一个 Agent 的声明：角色、提示、可用工具/技能、模型、预算。是数据，不是代码。 | Agent 模板、bot |
| **行动循环 Loop / Loop Strategy** | 驱动「规划→行动→观察」的可插拔策略（ReAct、plan-execute、reflexion…）。内核不内置某一种。 | agent loop（可接受）、主循环 |
| **工具 Tool** | 一个可被调用的能力，有输入 schema 与执行体；可能有副作用，需经策略与沙箱。 | 函数、function、action |
| **技能 Skill** | 一个声明式的「知识+指引」包（清单 + 指令/提示 + 资源 + 可选脚本）。注上下文、导行为，区别于「调用」。 | 能力、capability |
| **上下文构筑器 Context Builder** | 在每次模型调用前，assembling 出这一次要送进模型的上下文的组件（分层的：窗口/检索/记忆）。 | 提示组装、prompt builder |
| **模型网关 Model Gateway** | 对模型提供方的统一抽象与路由（含小模型路由、缓存、用量计量、预算）。 | LLM 客户端、provider |
| **记忆 Memory** | 跨会话/跨轮次的持久知识，按作用域（user/project/agent/run）存取。 | 长期存储、知识库 |
| **预算 Budget** | 一次 Run 的硬上限：步数、成本、超时。超限即停或转人工。 | 限额、quota |

## D. 治理与安全

| 术语 | 定义 | _避免_ |
|---|---|---|
| **策略 Policy** | 对每个动作判定 `allow / deny / ask / modify` 的规则集合。 | 权限、权限系统 |
| **审批者 Approver** | 对 `ask` 类动作给出裁决的角色：人或**辅助模型**（小模型）。 | 审核、reviewer |
| **辅助模型 Auxiliary Model** | 承担**判断类**辅助任务（权限审批、分类、抽取）的小模型——它**不是 Agent**，是一个可插拔的判定器。 | 小 agent、judge model |
| **能力 Capability** | 一个显式的、可列举、可撤销的权限令牌（读某目录、发网络请求…）。 | 权限、permission |
| **沙箱 Sandbox** | 隔离执行工具/代码的环境（本地进程 / 容器 / 远端）。 | 隔离、jail |
| **主体 Principal** | 由**宿主附加**、不可被调用方伪造的调用者身份（用户 / 项目 / Agent / Run 的组合归属）。策略判定的 subject、事件订阅过滤、记忆读写、UI 宿主桥鉴权，一律以它为准。 | 调用者、context.user |
| **动作摘要 Action Digest** | 被审批对象冻结后的规范化描述：执行主体、目标节点、工作区/资源身份、工具及实现版本、规范化参数、命令相关项。参数或目标一变，审批即失效。 | 审批快照、指纹 |
| **风险画像 Risk Profile** | 动作风险的四维评估：**数据修改 / 信息读取与外发 / 费用 / 代码执行与权限**。工具自报的 `sideEffect` 只是输入，最终取 `max(声明, 宿主评估)`。 | 风险等级、可逆性（单一维度不够） |
| **外发授权 EgressGrant** | 用户对「哪类内容可发给哪个接收方、用于什么用途」的显式授权（主模型 / 辅助审批 / 嵌入 / 反思分别授权）。 | 隐私开关、API Key 授权 |

## E. 扩展机制

| 术语 | 定义 | _避免_ |
|---|---|---|
| **扩展点 Extension Point** | 内核/插件公开的、允许他人贡献的位置（工具、技能、循环、审批者、UI 面板…）。 | 钩子、hook（hook 是更小的一种） |
| **贡献 Contribution** | 插件向某扩展点交付的具体内容。 | 注册项、entry |
| **清单 Manifest** | 插件的声明文件：id、版本、apiVersion、所需能力、贡献、激活事件、入口。 | 描述文件、config |
| **能力协商 Capability Negotiation** | 消费者声明所需、内核解析并匹配版本/能力的过程（P9）。 | 版本检查 |
| **安全扩展点 Security Extension Point** | 参与安全判定的扩展点（策略规则、策略求值器、审批者、沙箱、策略前置中间件）。普通插件对它们**只能收紧、不能放宽**；替换实现需用户显式信任。 | 安全插件、特权扩展点 |

### E′. UI 扩展（内嵌模型，见 ADR-0006）

| 术语 | 定义 | _避免_ |
|---|---|---|
| **区域 Region** | 外壳布局中一个可被插件填充的命名位置（header/main/sidebar/statusbar/overlay/modal…）。 | 槽位、slot |
| **视图 View** | 插件贡献到一个区域、由外壳渲染的一块内容。 | 组件、widget、面板 |
| **宿主桥 Host Bridge** | 外壳提供给插件 UI 的受控接口：读事件流、发命令；UI 不直接触碰内核状态。 | API、SDK |
| **插件档 Tier** | 插件的实现档位：T0 声明式 / T1 TypeScript（内嵌 JS 引擎）/ T2 原生（含自带 CLI）（内核侧）；D 声明式 / C 代码（UI 侧）。 | 等级、level |
| **性能逃生舱** | 插件自带原生 CLI/守护进程、经 `process.exec` 调用以获得原生性能的机制（仅桌面/服务端）。 | 加速、加速插件 |
| **内嵌 Embedded** | 插件 UI 只作为外壳布局树里的节点存在，插件**不创建独立窗口**。 | — |

## F. 数据与状态

| 术语 | 定义 | _避免_ |
|---|---|---|
| **事件 Event** | 一次状态变化的不可变记录，追加进日志。 | 消息、msg |
| **检查点 Checkpoint** | 一次 Run 的可恢复快照（用于中断恢复与换端）。 | 快照、snapshot |
| **读模型 Read Model** | 从事件派生的、供查询用的物化视图；可丢弃重建。 | 视图、view |
| **作用域 Scope** | 数据可见范围：`user / project / agent / run`。 | 命名空间、namespace |
| **追踪 Trace** | 一次运行的步骤级可观测记录。 | 日志、log（与 Journal 区分） |

## 术语之间的关系（一图速览）

```
节点 Node ──托管──▶ 会话 Session ──包含──▶ 轮次 Turn ──触发──▶ 运行 Run ──由…驱动──▶ 行动循环 Loop ──调用──▶ 工具 Tool
  │                                                                    │
  ├─运行─▶ 内核 Kernel + 插件 Plugin（贡献到 扩展点 Extension Point）      ├─读取─▶ 记忆 Memory
  │                                                                    └─受控于─▶ 策略 Policy ─验收于─▶ 审批者 Approver（可含 辅助模型）
  └─被─▶ 外壳 Shell ──附加──▶ 会话（本地或跨机）
                                                                   一切变化 = 事件 Event ──追加──▶ 日志 Journal
```

## 待定术语（讨论后落定）

| 候选 | 问题 |
|---|---|
| Skill vs Capability vs Plugin | 三者边界见上表，但「技能能否携带工具」的边界待定 |
| Node vs Server | 「服务端节点」是否要单独叫法，还是 Node 的一种 role？ |

> **已落定**：`Session` vs `Task` —— 两者分开，`Session` 是交互上下文（对话），`Task` 是命名目标（ADR-0008）；`Run` 必属一个 `Task`（数据上恒在，界面上可隐式）。
