## 0. 一句话

**上下文工程 = 把「模型此刻能看到的东西」当成内存层级来管；记忆 = 跨轮次/跨会话持久下来的事实。** 二者共用一条通道：**先按需检索、再分层组装、最后压缩到 Token 预算内。**

---

## 1. 上下文的分层（内存层级）

> 对应 `awesome-architecture/tutorial/22` 的内存层级思路：越上层越贵越快，越下层越便宜越持久。

```
   ┌───────────────────────────────────────────┐
   │ ① 上下文窗口（最贵最快，工作内存）            │  只放这一步真正需要的
   ├───────────────────────────────────────────┤
   │ ② 会话历史（本次会话，压缩后）               │  滚动摘要 + 关键原文
   ├───────────────────────────────────────────┤
   │ ③ 检索 RAG（按需取：项目文档/代码/政策）      │  双通道召回 + 重排
   ├───────────────────────────────────────────┤
   │ ④ 长期记忆（跨会话，落盘）                   │  事实 + 原文片段
   └───────────────────────────────────────────┘
        组装顺序：系统提示 → Agent 定义 → 技能 → ④/③ 检索 → ② 历史 → 上步观察
```

**取舍提醒**（`agent-research`）：长上下文 vs RAG vs 微调——**没有银弹**。塞整本简单但贵且糊；RAG 精准但要维护检索；微调改行为但僵化。默认 **RAG + 分层 + 压缩**。

## 2. ContextBuilder 与贡献者

**每次模型调用前，由 `context.contributor` 链组装上下文**（扩展点，见 `plugin-system.md`）。默认贡献者：
| 贡献者 | 注入什么 |
|---|---|
| 系统提示贡献者 | 全局规则、工具使用约定 |
| Agent 定义贡献者 | 角色、任务、可用工具/技能清单 |
| 技能贡献者 | 命中的技能正文与资源（渐进披露） |
| 记忆/检索贡献者 | 召回的事实与片段（带来源） |
| 历史贡献者 | 压缩后的会话历史 |
| 观察贡献者 | 上一步的工具结果/模型输出 |
| 预算贡献者 | 剩余步数/成本/时间的软提示（帮模型收敛） |

**规则**：贡献者**只读**、**不产生副作用**；每个贡献者声明自己的 **token 配额**，总量受 `TokenBudget` 约束（见 §3）。

> **只对 `main` 类调用生效**：辅助审批、摘要、嵌入这些**内部调用**不走贡献者链，用各自的受限路径（`model-gateway.md` §4.1）。否则「审批要组装完整上下文、组装上下文又要检索、检索又要调模型」会递归，也白白烧钱。

## 3. Token 预算与压缩

```
   TokenBudget = 模型上下文窗口 − 预留输出 − 安全余量
   各贡献者按配额取用；超配额 → 裁剪（优先级低的先丢）
```

**压缩机制**：
- **滚动摘要**：把久远的轮次压成摘要，保留最近 N 轮原文。**摘要不得抹掉来源信任等级**——合并多来源时取**最低等级**并标注「来源已合并」，否则摘要会成为绕过来源约束的洗白通道（`policy-and-approval.md` §8）。
- **原文外置**：大块内容进 Blob，上下文只放引用 + 摘要。
- **按需展开**：技能/参考文档先给 description，命中才展开（渐进披露）。
- **裁剪优先级**：系统提示/Agent 定义 > 当前任务 > 最近观察 > 历史摘要 > 旧检索结果。

> 上下文爆掉时的正确反应是**压缩/裁剪**，不是直接失败（`model-gateway.md` §6）。

## 4. 记忆的本质：事实 + 原文

> 依据 `agent-research` 记忆 MVP：**事实表是 Source of Truth + Episode 存原文。**

| 概念 | 作用 |
|---|---|
| **Episode** | 原始片段（对话、文档、工具结果），不可变，按来源与时间归档 |
| **MemoryRecord** | 从 Episode **提炼**出来的事实，可检索、可失效、可版本化 |

**写入前过准入（Admission Barrier）**：
```
候选事实 ──▶ 准入判定（是否值得记？是否与既有冲突？敏感吗？）
               │ 通过 ──▶ MemoryAdmitted（落为 Active）
               └ 不通过 ─▶ MemoryRejected（可留作 Episode，不成为事实）
```
- 避免把噪声/一次性信息塞进长期记忆（记忆膨胀是头号问题）。
- 准入可由**规则**或**辅助模型**执行（不是主 Agent）。

## 5. 记忆的数据模型（核心不变量）

承接 `domain-model.md` §7：

| 字段 | 作用 |
|---|---|
| `attribution` | **归属**：属于哪些主体（用户/项目/Agent/Run 的组合） |
| `visibility` | **可见范围**：谁有权读（由宿主按 `Principal` 校验） |
| `fact` | 事实内容（Source of Truth） |
| `validFrom` / `validTo` | **生效区间**（bi-temporal：事实何时为真） |
| `recordedAt` | 系统何时**记录/知道** |
| `invalidatedAt` | 系统何时**不再采信**（撤销的事务时间） |
| `supersededBy` | 版本链：被谁取代 |
| `episodeRef` | 来源原文 |
| `sourceTrust` | 来源信任等级（外部内容低于用户输入） |
| `confidence` | 置信度 |
| `state` | `Active / Invalidated / Superseded` |

**铁律**：
- **失效 ≠ 删除**：`Invalidated` 保留，默认检索不再命中，但可追溯。
- **遗忘 ≠ 删除**：可设 TTL/降权，不物理删（除非用户显式删除）。
- **版本链**：新事实取代旧事实时，旧记录 `supersededBy` 指向新记录。
- **双时间**：`validFrom/validTo`（事实何时为真）+ `recordedAt`（何时知道）+ `invalidatedAt`（何时撤销）——三者齐全才支持「回看到当时」与「当时系统知道什么」。
- **归属 ≠ 授权**：见 §8。

### 5.1 变更操作契约（补上「只有 add/search」的缺口）

```
add(candidate, attribution)        # 过准入 → 落事实/原文
search(query, principal, opts)     # 双通道召回 + 权限过滤 + Receipt
supersede(oldId, newFact)          # 新事实取代旧的（旧记录 Superseded）
invalidate(recordId, reason)       # 置 Invalidated + invalidatedAt（不删除）
correct(recordId, rightFact, why)  # 纠错 = supersede + 标注「纠正」原因
forget(scopeSelectors)             # 用户显式删除（跨存储，见 §5.2）
```

> 「失效 / 替代 / 纠错 / 用户删除」此前只是**承诺**，没有对应操作——现在补齐。没有操作契约的生命周期不是设计，是愿望。

### 5.2 删除与脱敏（跨存储）

用户显式删除必须覆盖**完整数据链**，否则「删了」只是删了索引：

1. 事实记录、派生索引（向量/BM25）、Episode、Blob、检查点中的副本。
2. **未来的同步副本**：已复制的节点需收到删除事件并执行（`MemoryForgotten`）。
3. 删除本身留**审计记录**（谁在何时删了什么类别），但**不保留内容**。

**写入侧脱敏**：Episode 落盘前做**秘密识别与脱敏**（密钥、令牌、私钥、连接串）。用户输入、终端输出、工具结果**都可能含秘密**——不能只保护配置里的密钥。识别不了的一律按最低信任等级处理。

## 6. 检索（`retrieval.strategy`）

> 依据 `agent-research` 搜索线 v1 最小集；注意若干纠错（见下）。

### 6.1 双通道召回 + 重排

```
   查询 ──┬─▶ 向量召回（语义相似）──┐
          └─▶ BM25 召回（关键词）──┼─▶ 融合(融合前需时间过滤) ─▶ 本地重排 Top-5~10 ─▶ 置信门控 ─▶ 注入上下文
                                   │
                    作用域过滤(user/project/agent/run) + 时间过滤(validTo 过期剔除)
```

**硬要求（来自调研）**：
- **BM25 必须是独立召回通道**，不能被向量吞掉（否则精确匹配/专有名词召回差）。
- **融合**：RRF 默认 k **不要写死 60**——Qdrant 源码 `DEFAULT_RRF_K = 2`；按自测数据调。
- **每条结果附 Receipt**：来源、时间、置信度，便于模型引用与人审查。
- **置信门控**：召回到的相关度低于阈值 → 不注入（宁缺毋滥，避免噪声误导）。

### 6.2 查询增强（可选）

- **HyDE**：先让模型写一个假设答案，再用它增强检索。
- 仅在「问题模糊、召回差」时启用，避免无谓成本。

## 7. 接口：薄而稳定

```ts
// 记忆接口：薄，但必须覆盖已承诺的生命周期
memory.add(candidate, attribution)             // 过准入 → 落事实/原文
memory.search(query, principal, opts) -> Receipt[]
memory.supersede(oldId, newFact)               // 版本链
memory.invalidate(recordId, reason)            // 失效不删
memory.correct(recordId, rightFact, why)       // 纠错
memory.forget(scopeSelectors)                  // 用户显式删除（跨存储）
```

**为什么薄**：底层可从 SQLite（初期）换到向量库/图库（后期）而不惊动上层；**初期不上图库**，等「多跳检索」成为瓶颈再引入（`agent-research` 的「去图库化」建议）。

> 注意 `search` 的第二个参数是 **`principal`（宿主提供）**，不是调用方随意传的 `scope`——这是「不能靠传参换权限」的落点。`opts` 里可以有作用域过滤，但只能**收窄** `principal` 已允许的范围。

## 8. 作用域：归属与可见性分开 ⭐

> 原表把「作用域」同时当**分类**与**授权**，于是出现「user 记忆该用户所有会话可读」与「run 不可读 user 私有」并存——两句话都对，但说的是两件事。

| 维度 | 回答 | 例 |
|---|---|---|
| **归属 attribution** | 这条事实**来自**谁 | 「用户在项目 P 里说的偏好」 |
| **可见范围 visibility** | 谁**有权读** | 「同一用户在当前项目可读」 |

| 归属 | 典型可见范围 | 例 |
|---|---|---|
| `user` | 该用户**有权访问**的会话（跨项目需明确共享） | 偏好、习惯 |
| `project` | **该项目**下的会话 | 项目术语、架构决策 |
| `agent` | 该 Agent 定义实例 + 其所在项目 | Agent 专属知识 |
| `run` | 单次运行（临时工作记忆） | 本次任务的中间结论 |

- **「属于 Run」不意味着只能读 run 级数据**：当前 Run 可以读取其 `Principal` 有权访问的用户偏好、项目知识、Agent 记忆。
- **同一 Agent 用在不同项目，不自动共享项目记忆**：项目作用域以项目身份隔离（否则会跨项目串记忆）。
- **可见性由宿主按 `Principal` 校验**：插件不能通过传入另一个 scope 获得权限；扩大可见范围是**明确的共享操作**（用户发起，落事件）。
- 敏感记忆（密钥、身份）不进记忆库；若必须引用，存**引用**不存原文。
- 记忆是**本地优先**的：默认落本地，跨端同步是增强；**内容外发给远端模型/嵌入服务另需 `EgressGrant`**（`model-gateway.md` §7.2）。

## 9. 评估（从第一天起）

> `agent-research` 反复强调：**从第一天建 golden 评估集**，否则记忆/检索质量悄悄退化不可察。

- 100–200 条代表性查询 + 期望命中，做成评测集进 CI（`70-quality/evaluation.md`）。
- 指标：recall@k、命中率、噪声率、Receipt 准确度。
- 改检索策略/换嵌入模型/改准入规则前，先跑评估。

## 10. 与循环的接口

- 循环每步调 `context.assemble(runCtx)`；它内部走贡献者链 + 检索（§2）。
- 循环结束时，把「值得记的」候选交给 `memory.add`（过准入）。
- **记忆写入不阻塞循环**（异步/最终一致亦可），但**检索在热路径上**（要有超时兜底：检索失败 → 降级为无记忆上下文，不阻断）。

## 11. 反模式

- ❌ **把整段历史塞进窗口** → ✅ 分层 + 压缩。
- ❌ **只有向量、没有 BM25** → ✅ 双通道。
- ❌ **RRF k 写死 60** → ✅ 按数据调（Qdrant 默认 2）。
- ❌ **写入不过准入** → ✅ Admission Barrier。
- ❌ **失效即删除** → ✅ 失效不删、版本链。
- ❌ **一上来就上图库** → ✅ 初期 SQLite，多跳成瓶颈再引入。
- ❌ **检索无置信门控** → ✅ 低相关不注入。
- ❌ **记忆写入阻塞主循环** → ✅ 异步写、热路径只读且有超时降级。
- ❌ **归属当授权用** → ✅ 归属与可见性分开，宿主按 `Principal` 校验。
- ❌ **只保护配置里的密钥** → ✅ 用户输入/终端输出/工具结果也脱敏。
- ❌ **删除只删索引** → ✅ 覆盖 Blob、检查点、派生索引与已复制的副本。
- ❌ **摘要丢掉来源等级** → ✅ 合并取最低等级并标注。
- ❌ **内部调用也走完整上下文组装** → ✅ 按 `callClass` 走受限路径。
