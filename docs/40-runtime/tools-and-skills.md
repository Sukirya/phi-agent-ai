# 工具与技能

> 状态：🌿 · 最后更新：2026-11-08
> 上游：`20-domain/domain-model.md` §5（ToolInvocation/状态机）、`30-extension/plugin-system.md`（provider.tool / content.skill）
> 关联：`40-runtime/policy-and-approval.md`（闸门）、`40-runtime/agent-loop.md`（谁在调用）

---

## 0. 一句话

- **工具（Tool）= 可被调用的能力**，有输入 schema 与执行体，可能有副作用 → **需要过策略与沙箱**。
- **技能（Skill）= 可被触发的知识/指引包**，声明式（清单 + 指令 + 资源），**注上下文、导行为**，不直接产生副作用。

> 一句话区分：**工具是「动词」（做事），技能是「手册」（告诉你怎么做）。** 二者都可插件化，但生命周期、风险、注入方式完全不同。

---

## 1. 工具（Tool）

### 1.1 定义

| 字段 | 说明 |
|---|---|
| `id`, `version` | 稳定标识 + 版本 |
| `name`, `description` | 给模型看的名称与描述（**这是模型选择工具的主要依据**） |
| `inputSchema` / `outputSchema` | 结构化契约（JSON Schema） |
| `sideEffect` | `none / reversible / irreversible` ← **声明，不是判决**：策略据此起步，最终由宿主的四维风险画像判定（ADR-0010、`policy-and-approval.md` §5） |
| `idempotent` / `idempotencyKeySpec` | 工具是否支持幂等键（恢复与重试依赖它，见 `agent-loop.md` §8.1） |
| `providerRef` | 执行体来自哪个插件（T1 TS / T2 原生 / 自带 CLI） |
| `requires` | 所需能力（`fs.rw`、`net.http`、`process.exec`…） |

**不变量**（承接 `domain-model.md`）：
- `I-5-1` **没有 PolicyDecision 就不得执行**。
- `I-5-2` `irreversible` 默认走 `ask`（可被策略配置覆盖，但需显式）。
- `I-5-3` 外部 schema（MCP）经**防腐层**翻译后才入册。

### 1.2 工具来源

| 来源 | 说明 | 档 |
|---|---|---|
| **内置插件** | 随产品发布的基础工具（读写文件、执行命令、搜索…） | T1/T2 |
| **第三方插件** | 用户安装的插件贡献的工具 | T1/T2 |
| **MCP** | 外部 MCP Server 暴露的工具，经发现层接入 | 经 ACL 转译 |

> 内置与第三方走**同一套**注册与闸门，无特权路径（`plugin-system.md` 原则）。

### 1.3 工具调用生命周期

```
Requested ──policy──▶ Denied（终态，可审计）
    │
    ├──policy(allow)────▶ Executing ──▶ Succeeded / Failed
    │                                  └─ 可能已执行、无法查证、非幂等 ──▶ OutcomeUnknown（待核对）
    │
    └──policy(ask)──▶ AwaitingApproval ──批准──▶ Executing / 驳回──▶ Denied
```

每一步产出事件：`ToolInvokeRequested / ToolInvokeDecided / ToolInvokeStarted / ToolInvokeCompleted / ToolInvokeFailed / ToolInvokeOutcomeUnknown`。

> `OutcomeUnknown` 不是失败：它表示「可能已经发生了副作用，但我们不知道」。此时**不自动重试**，Run 进入 `AwaitingReconciliation`，由人核对。

### 1.4 结果处理

- **截断**：超长结果按策略截断或摘要（避免塞爆上下文）。
- **大对象外置**：图片/大文件/日志走 Blob，上下文里只放**引用 + 摘要**（`ContentRef`）。
- **结构化优先**：能用结构化输出就别回大段文本（省 token、好渲染）。
- **回灌**：结果作为 Observation 进入下一步上下文（`agent-loop.md` §6）。

## 2. 技能（Skill）

### 2.1 定义（声明式包）

一个技能是一个目录：

```
skills/<skill-id>/
├── SKILL.md          # 清单 + 指令（frontmatter: name/description/invocation）
├── REFERENCE.md      # 可选：详细参考，按需加载
├── assets/           # 可选：模板、样例、数据
└── scripts/          # 可选：脚本（可被工具调用）
```

| 字段 | 说明 |
|---|---|
| `name`, `description` | 何时该用这个技能（**模型据此决定是否触发**） |
| `invocation` | `model`（模型可自动触发）/ `user`（仅用户显式调用） |
| `body` | 指令正文（注入上下文） |
| `resources` | 附带文件（渐进披露，按需读） |
| `bundledTools` | 可选：技能自带的小工具 |

> 与 `skills/` 参考库的格式对齐（`SKILL.md` + `name/description` + 渐进披露 + 小而可组合）。

### 2.2 技能的关键性质

- **注上下文，不产生副作用**：触发技能 = 把指令/资源放进上下文，不改世界。
- **渐进披露**：先只加载 `description`（省上下文），命中后才加载正文与资源。
- **可触发时机**：会话开始 / 模型判断相关 / 用户显式 `/skill` / 任务匹配。
- **可组合**：技能之间可被引用；一个技能可要求某工具存在（由编排者解析）。

### 2.3 技能 vs 工具 vs 能力

| | 技能 Skill | 工具 Tool | 能力 Capability |
|---|---|---|---|
| 本质 | 知识/指引 | 可调用动作 | 权限令牌 |
| 副作用 | 无 | 有（需闸门） | 它授权副作用 |
| 注入方式 | 上下文 | 模型发起调用 | 内核发给插件 |
| 谁来用 | 模型/用户 | 模型 | 插件/工具 |

**边界规则**：「告诉模型怎么做」放技能；「让模型做一件事」放工具；「允许插件碰什么」放能力。三者不混。

## 3. 工具发现与选择

模型要在**数量可观**的工具里选出对的那个。策略（可插拔）：

| 方式 | 说明 | 适用 |
|---|---|---|
| **全量暴露** | 所有工具 schema 都进上下文 | 工具少（< 几十个） |
| **分组/命名空间** | 按来源或领域分组，按需展开 | 中等规模 |
| **检索式暴露** | 用工具的描述做检索，只把相关的几个送进模型 | 工具极多（借鉴 Gorilla 的工具检索） |

默认从「全量 + 分组」起步；工具集变大再上检索（`agent-research` 的渐进建议）。

## 4. MCP 接入（发现层 + 防腐层）

> `agent-research`：MCP 是**跨厂商工具发现层**；Host 必须自己做 schema 转译、审批、审计与沙箱。最大风险是恶意 Server 的提示注入。

```
外部 MCP Server ──工具列表──▶ plugin-mcp（发现层）
                                   │
                          防腐层转译 schema + 标注 sideEffect
                                   │
                                   ▼
                          入内部工具注册表（此后等同内置工具）
                                   │
                          调用时：策略闸门 + 沙箱 + 审计（一视同仁）
```

**铁律**：
- **MCP Server 的返回内容不可信**（防提示注入），信任等级最低（`policy-and-approval.md` §8）。
- MCP 工具**不获得特权**——与内置工具同级过闸门。
- **外部 MCP 的执行不受本机沙箱约束**：Server 跑在别处，本机只能约束「发出去什么、收回来什么」，不能约束它在自己那边做什么。见 §5.2。
- 断连/超时有降级，不阻塞主循环。

## 5. 隔离边界：三种情况不能混为一谈 ⭐

> 「允许执行某个二进制」≠「限制这个进程能干什么」。原文档把进程、原生插件、远程 MCP 的隔离保证混在一起，这里分开。

### 5.1 三类执行体，各自的隔离机制与信任前提

| 执行体 | 实际隔离机制 | 信任前提 | 平台不支持时 |
|---|---|---|---|
| **T1 插件（内嵌 JS）** | QuickJS 引擎沙箱；无隐式系统调用、无直接文件/网络句柄；只能经宿主能力接口 | 引擎隔离 + 能力令牌 | 全端支持 |
| **自带 CLI 子进程** | **进程边界**——它是独立进程；可套 `provider.sandbox`（进程沙箱/容器）设 CPU/内存/超时 | 二进制是插件包的一部分，信任级别**等同该插件** | 移动端不支持 → 拒绝加载该插件 |
| **T2 进程内原生库** | **几乎没有隔离**——它与宿主同地址空间，**持有宿主权限** | 需**白名单**，只有受信插件才允许 | 不适用 |
| **远端 MCP Server** | **本机无法隔离**——它在对端执行 | 按**外部不可信**处理：只约束出入（schema 转译、内容信任等级、能力限制），其内部行为不在我们控制内 | 不适用 |

**要点**：

- **「只允许执行包里那个二进制」只是限制「执行哪一个」，不限制「它执行后能碰什么」**。真正的约束来自进程沙箱的**文件/网络/子进程策略**——必须显式配置，否则二进制默认继承用户权限。
- **进程内原生插件是特权档**，不是「快一点的插件」。它必须走白名单且用户显式同意。
- **远端工具的风险靠「不信任它的输出 + 限制它的输入」**，不能靠本机沙箱。

### 5.2 沙箱档位（用于 T1/CLI 的执行）

| 档 | 强度 | 适用 | 默认约束 |
|---|---|---|---|
| **进程沙箱** | 中 | 一般工具、插件自带 CLI | 限 CPU/内存/超时；**文件与网络按能力白名单** |
| **容器** | 高 | 执行第三方代码/不可信脚本 | 只挂载工作区；默认无网络 |
| **远端** | 高 | 需与宿主彻底隔离，或借用算力 | 数据外发需 `EgressGrant` |

**默认**：有副作用的工具默认在**进程沙箱**里跑；执行**不可信代码**默认进**容器**或远端。**无沙箱跑需要显式豁免并记录理由**——且豁免本身属于用户的显式管理操作（ADR-0010）。

## 6. 权限（能力）

- 工具在清单里声明 `requires`（如 `fs.rw:${workspace}`）。
- 内核按最小授权发放**能力令牌**；未声明的调用直接失败。
- **声明 ≠ 放行**：每次副作用仍过策略（可能 `ask`）。

## 7. 编码场景示例（Q4：首批形态）

| 名称 | 类型 | sideEffect | requires | 闸门默认 |
|---|---|---|---|---|
| `fs.read` | 工具 | none | `fs.read:${workspace}` | 自动允许（工作区内）——**但读凭据类文件不属此类**，由策略的 `deny-secret-exfil` 拦下 |
| `fs.write` | 工具 | reversible | `fs.write:${workspace}` | 允许（工作区内，**需备份/回滚条件**）/ 出界则 ask |
| `shell.exec` | 工具 | irreversible | `process.exec` | **ask**（默认） |
| `search.code` | 工具 | none | `fs.read:${workspace}` | 允许 |
| `git.commit` | 工具 | irreversible | `process.exec:git` | **ask** |
| 「项目架构地图」 | 技能 | — | — | 模型可触发，注入上下文 |
| 「提交规范」 | 技能 | — | — | 用户 `/提交规范` 触发 |

> 这张表里的 `sideEffect` 是**工具的自我声明**。第三方工具或 MCP Server 可以对同样的操作声明 `none`——所以策略真正依赖的是**宿主评估的四维风险**（`policy-and-approval.md` §5），声明只用来做初筛。

## 8. 反模式

- ❌ **工具无 schema / 靠自然语言描述** → ✅ 结构化 schema + 描述（模型靠它选）。
- ❌ **信任 MCP/工具返回内容** → ✅ 当不可信输入，防注入。
- ❌ **把「怎么做」写进工具** → ✅ 拆成工具（做）+ 技能（指引）。
- ❌ **有副作用却默认无闸门** → ✅ 默认过策略；不可逆默认 ask。
- ❌ **工具结果整段塞回上下文** → ✅ 截断 + 摘要 + Blob 引用。
- ❌ **一个工具包打天下** → ✅ 小而正交，按命名空间/检索暴露。
- ❌ **信工具自报的 `sideEffect`** → ✅ 声明只作初筛，风险由宿主四维判定。
- ❌ **「只允许执行这个二进制」当成隔离** → ✅ 进程沙箱的文件/网络/子进程策略才是隔离。
- ❌ **把进程内原生插件当普通插件** → ✅ 它是特权档，走白名单。
- ❌ **以为本机沙箱能约束远端 MCP** → ✅ 只约束出入，内部行为不可控。
