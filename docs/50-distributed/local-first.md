# 本地优先

> 状态：🌿 · 最后更新：2026-11-08

---

## 0. 一句话

**每个节点都有一份完整、可写、可读的本地事实源；断网时功能照常（除天然需网络的模型调用）；跨端同步是可选的增强，不是运行前提。**

---

## 1. 本地优先的三层含义

| 层 | 含义 | 反面（要避免的） |
|---|---|---|
| **本地事实源** | 会话、事件、记忆、配置默认存在本机 | 启动先向服务器拉数据 |
| **离线可用** | 断网仍能开、能看、能继续（本地模型/已有上下文） | 断网即白屏 |
| **同步增强** | 联网时跨端协同；不联网也能独立跑 | 「必须有服务器才能用」 |

> 这是 F2「每端都能单独运行」的根。若一个端必须依赖中心才能工作，它就不是「独立的端」。

---

## 2. 每个节点都是完整的

```
   节点（桌面/手机/服务器）
   ┌─────────────────────────────────┐
   │ 本地事件日志 Journal（事实源）     │
   │ 本地读模型（从日志派生，可重建）    │
   │ 本地记忆库 / Blob 存储            │
   │ 本地配置 / 密钥（Keychain）        │
   └─────────────────────────────────┘
```

- 节点**不区分「主/从」**（ADR-0004）。服务器只是「常开、能力强」的普通节点。
- 每个节点都能**独立启动、独立完成任务**。
- 没有「必须先同步才能工作」的状态。

---

## 3. 同步单元：会话的事件日志

承接 ADR-0002：会话/运行主线是事件溯源。**同步的最小单元 = 某会话的事件日志（journal）**。

- **会话级线性 `seq`**：由写者分配，在整条会话日志内单调递增、无空洞（全序）。它负责**续传与去重**——读者只关心「我收到第几号事件」。
- **聚合内 `aggregateVersion`**：每个事件同时携带 `aggregateId + aggregateVersion`，是该**聚合内**的序号。它负责**聚合重建**（回放到某版本即得到该聚合状态）与**乐观并发**（`expectedVersion`）。
- **`seq ≠ aggregateVersion`**：一条会话日志交错着多个聚合（Session、Run、Task…）的事件；`seq` 是日志的全局行号，`aggregateVersion` 是每个聚合各自的行号。两者都单调，但**不是同一个计数器**，不能混用。
- 复制 = 把对方的 journal 从某 `seq` 续传到本地；状态由事件折叠而来——**复制了事件，就复制了状态**（不必传物化快照，虽可传检查点加速）。

**订阅游标 = 会话 `seq` + 各聚合版本向量**：`seq` 决定「还没收到哪些事件」，版本向量决定「本地各聚合已重建到哪」。只记 `seq` 不足以判断某个聚合是否完整（事件可能乱序到达或多路复制）；只记版本向量不足以续传日志。

**单调时钟不承担持久排序**：墙钟/单调时钟跨设备、跨重启都不可靠，**不得**用于事件排序、比较或去重。它只用于**进程内超时与耗时测量**（心跳、重试退避、UI 进度）。持久顺序只由 `seq` / `aggregateVersion` 表达。

**为什么用事件日志而不是「当前状态」**：当前状态会覆盖、会冲突、会丢历史；事件日志只追加，天然可续传、可回放、可审计。

## 4. 一致性模型（v1）

**v1：单写者 + 附加（attach）。**

| 角色 | 能做什么 |
|---|---|
| **写者节点**（owner） | 唯一能往会话追加事件、推进 Run |
| **附加外壳**（attach viewer） | 只读事件流 + 发**命令**（命令被写者接收后才生效） |

- 一个会话同一时刻只有一个写者（`I-2-1`）。
- attach 是「遥控」：外壳发的命令经写者转成事件，**不是外壳自己写**。
- 因此 v1 **没有写写冲突**——这是有意的简化（你说「只支持最基础的协同」）。

**为什么单写者**：Agent 事件流有**严格因果与顺序**（思考→行动→观察），多写者的自动合并会破坏这个语义。多写复制留到 R2，见 §5。

---

## 5. 多写复制（R2，预留）

当需要「多端同时写同一会话」时：

- **不要**对 Agent 事件流直接用通用 CRDT——因果顺序会被打乱，且「观察」依赖前序「行动」。
- 可行路线：**命令汇聚到单一逻辑写者**（逻辑单写、物理多活），或**按子流分区**（不同 run 由不同节点写，按 run 隔离），再对少量共享字段（如标题、标签）用 CRDT。
- **结论**：R2 是「分区 + 逻辑单写」的工程，而非「什么都能 CRDT」。v1 不做。

## 6. 离线与重连

```
   离线：本地继续追加事件（seq 照增）
     │
   重连：与对端交换游标（会话 seq + 各聚合版本向量）
     │
   差集：按 seq 续传缺失事件（幂等，事件不可变，重复即忽略）
     │
   收敛：双方折叠出相同状态
```

- 事件**不可变**，所以重传安全（幂等）。
- 断点续传靠**游标** `(sessionId, lastSeq, aggregateVersions)`：`seq` 决定补发哪些事件，各聚合版本向量决定本地各聚合是否已重建到位。事件去重只按 `(sessionId, seq)`；版本向量不参与去重。
- **互不依赖**：离线期间各自独立推进的会话，不需要「谁赢」——它们本就属于不同会话/不同写者。

## 7. 数据所有权与隐私

**「默认本地」说的是存储，不是外发。** 存储留在本机，与「是否会发给模型/服务」是两件事，必须分开授权。

| 维度 | 默认 | 由谁控制 |
|---|---|---|
| **存储** | 本地（会话、事件、记忆、Blob、配置） | 用户；同步是显式选择 |
| **外发** | 不自动外发 | `EgressGrant`（接收方 / 用途 / 内容类别） |

- **外发由 `EgressGrant` 控制**：一项授权至少写明**接收方**（哪个 provider/服务）、**用途**（主模型推理 / 辅助审批 / 嵌入 / 摘要）、**内容类别**（对话、记忆、文件…）。四类用途**分别授权**——允许主模型不等于允许用同一批数据做嵌入或摘要。
- **降级只能在已授权服务集内**：主模型不可用时可回退到备用 provider，但备用方必须已在 `EgressGrant` 中；**不得**因为降级把一个未授权接收方拉进来。
- **「仅本地」模式必须被路由与降级遵守**：用户选「仅本地」后，路由不得调用任何远程模型，降级也不得偷偷外发；此时只有本地模型可用，没有本地模型就明确失败，而不是降级到云端。
- **外发留痕**：`EgressGranted` / `EgressRevoked` 进事件日志，可审计「哪条数据在何时、以什么用途发给了谁」。
- **同步是显式选择**：用户决定哪些会话/哪些端参与复制。
- **密钥**：OS Keychain / 等效加密，永不进日志/事件/上下文（`model-gateway.md` §7）；密钥不属于任何 `EgressGrant` 的内容类别。
- **端到端**（预留）：跨公网复制时可加密，中继不可读（若未来引入中继，ADR-0004 的 C 方案）。

## 8. 本地数据的升级与灾难恢复

本地是事实源，就必须像对待数据库一样对待它：**能备份、能检测损坏、能回滚、旧事件永远可读**。

### 8.1 一致备份

- **数据库与 Blob 必须在同一快照点备份**。事件里引用 Blob（用户输入、工具产物、附件），只备份数据库会得到一堆悬空引用；只备份 Blob 则丢失索引与顺序。
- 备份是**一致性快照**，不是「边跑边拷文件」：先取得快照点，数据库与 Blob 都按该点导出。
- 恢复后要能验证：做引用完整性检查（每个 Blob 引用都能解析到对象）。

### 8.2 数据库损坏 / 磁盘满

| 情况 | 行为 |
|---|---|
| 检测到数据库损坏 | 进入**只读模式** + 明确提示（可读、可导出、可备份；不可追加） |
| 磁盘空间不足 | 写入前预留检查；不足则**拒绝写入并提示**，而不是写一半 |
| 写入中断 | 单条事件写入原子；**不允许半写**（要么整条落盘，要么没有） |

- 损坏检测要区分「打不开」与「能打开但页校验失败」；后者同样按只读处理。
- 只读模式是**明确的用户可见状态**，不是静默降级。

### 8.3 升级失败

- **迁移前必须备份**；迁移失败可回滚到迁移前状态（数据库 + Blob 一起回滚，保持同一快照点）。
- 迁移是**单向**的：升级后旧程序可能读不了新 schema，因此要写**版本标记**（schema 版本），阻止旧版本误开新库。
- 升级要么完成、要么回到升级前，不留下「迁移到一半」的库。

### 8.4 插件删除/升级后的历史事件

- **事件 schema 只增不改**：内核事件字段只追加、不复用、不改语义；旧事件在新版本里仍按原样解析。
- **插件特有事件需要兼容层**：插件删除或升级后，旧 payload 可能已不符合新代码。由**插件作者**提供 `upcast`（旧 payload → 新 payload）或 `fold`（把旧事件折叠成等价的新事件）；缺失时该事件**降级为「不可解析，保留原文」**，UI 显示原始 payload，**不得丢弃**。
- **「旧事件永可读」的责任划分**：
  - **内核**保证**信封**可读（`sessionId` / `seq` / `aggregateId` / `aggregateVersion` / 类型 / 时间 / 签名）；
  - **插件**保证 **payload** 的 `upcast`；插件不提供，就只能读信封、读原文，不能重建该插件的语义。
- 删除插件**不等于**删除其历史事件：事件是事实，保留；只是暂时缺少解释它的代码。

## 9. 与事件溯源的关系（ADR-0002）

本地优先之所以能「可换端、可离线、可审计」三合一，靠的就是事件日志作为事实源：

| 需求 | 事件日志怎么满足 |
|---|---|
| 离线 | 本地追加，不依赖网络 |
| 续传/复制 | 按 seq 续传 |
| 换端 | 复制事件 + 检查点即可继续（`handoff.md`） |
| 审计/回放 | 事件本身可回放 |

## 10. 反模式

- ❌ **启动先拉服务器数据** → ✅ 本地为零依赖，后台同步。
- ❌ **把「当前状态」当同步单元** → ✅ 事件日志（只追加、可续传）。
- ❌ **对 Agent 事件流直接用通用 CRDT** → ✅ 单写者（v1）/ 分区 + 逻辑单写（R2）。
- ❌ **同步是默认强制** → ✅ 同步是显式增强。
- ❌ **密钥进事件/日志** → ✅ Keychain + 不进事件。
- ❌ **备份只拷数据库、不拷 Blob**（或反之） → ✅ 数据库与 Blob 在**同一快照点**备份。
- ❌ **升级前不备份、迁移不可回滚** → ✅ 迁移前备份 + 版本标记 + 可回滚。
- ❌ **删除插件后丢弃其历史事件** → ✅ 保留事件，缺 `upcast` 时降级为「不可解析，保留原文」。
