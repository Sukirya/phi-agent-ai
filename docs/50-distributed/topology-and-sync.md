## 0. 一句话

**phi-agent 的网络是一张「对等节点」图：每台设备是一个节点；外壳通过统一传输附加到某个节点；会话的事件日志在节点间按需复制。没有中心，没有「必须在线」的角色。**

---

## 1. 节点与角色

| 概念 | 说明 |
|---|---|
| **Node** | 一台设备上的一个运行实例；有稳定身份、能力清单（CPU/工具/网络/是否常开）、地址 |
| **Role（描述性）** | 节点可标注 `desktop / mobile / server`，但这只是**能力描述**，不是主从关系 |
| **Shell** | 外壳，连接到某节点；可以是同机（进程内）或跨机 |

> **服务器不是特殊物种**：它只是「常开、算力强、通常无 UI」的普通节点。它可以被选作执行位置、也可以是 attach 目标、换端目标——但缺了它，其他节点照常工作（ADR-0004）。

---

## 2. 三种连接（都收敛到同一套契约）

```
   ┌──────────────┐  ① 进程内（同机）   ┌──────────────┐
   │ 外壳 Shell   │◀── Tauri IPC ────▶│  节点 Node   │
   └──────────────┘                    │ （同一进程）  │
                                       └──────────────┘

   ┌──────────────┐  ② 局域网          ┌──────────────┐
   │ 外壳（手机）  │◀── WebSocket ────▶│ 节点（桌面）  │
   └──────────────┘                    └──────────────┘

   ┌──────────────┐  ③ 跨公网（预留）   ┌──────────────┐
   │ 外壳（任意）  │◀── WS/HTTPS ─────▶│ 节点（服务器）│
   └──────────────┘   （NAT 穿透/中继）  └──────────────┘
```

**统一契约**：外壳与节点之间只有两样东西——**命令（command，外壳→节点）** 与 **事件流（event stream，节点→外壳）**。三种传输只是同一契约的不同适配器（P2）。这让同一套 UI 能连任意节点（`60-frontend/`）。

---

## 3. 身份与信任（节点对节点）

```
   节点身份 = 密钥对（公钥即身份）
   配对     = 交换公钥并建立信任（二维码 / 一次性码 / 局域网发现）
   信任     = 双向、显式、可撤销；不隐式继承
```

- **没有中心权威**：信任是两台设备之间直接建立的（ADR-0004）。
- **配对一次，信任长期**；每次连接仍需**鉴权**（证明持有私钥）。
- 信任关系决定：是否允许 attach、是否允许复制、是否允许换端。
- 撤销信任 = 断开并拒绝后续连接。

---

## 4. attach（v1 协同的基本形态）

**目标**：在 A 端看/控 B 端上的会话。

```
   外壳(A) ──command──▶ 节点(B)          # 发送命令（如「继续」「暂停」「审批通过」）
   外壳(A) ◀──events─── 节点(B)          # 订阅事件流，实时渲染
                        │
                     写者仍是 B（单写者）
```

- 外壳**不直接写会话状态**；它发命令，B 决定是否转成事件。
- 事件流**可续订**：断线后按 `(sessionId, lastSeq)` 续传，不漏事件。
- 多个外壳可同时 attach 同一会话（只读视角），互不干扰。

**连接握手（bootstrap + 查询）**：attach 不是一上来就订阅，而是三步：

```
   ① hello      外壳 ──「协议版本 / 能力 / 插件状态版本」──▶ 节点
   ② query      外壳 ◀── 快照 + 游标（session seq + 各聚合版本向量）── 节点
   ③ subscribe  外壳 ──「subscribe(sessionId, cursor)」──▶ 节点（此后增量推送事件）
```

- **先 `hello`**：交换 `protocolVersion`、能力清单、**插件状态版本**——不匹配则明确拒绝或降级，不硬连。
- **再 `query`**：取当前快照与游标，外壳据此渲染首屏；**分页历史也走 `query`**（不靠订阅把历史全推一遍）。
- **后 `subscribe(sessionId, cursor)`**：从游标开始只收增量事件，避免全量重推。

**v1 范围**：同机 + 局域网。跨公网 attach 需要 NAT 穿透/中继，列为 R2（Q1′）。

## 5. 复制（R2，预留）

**目标**：两个节点各持有某会话的一份副本，各自可读，最终一致。

```
   节点 A  ── 交换 (sessionId, seq) ──  节点 B
              │
       差集：A 有 seq 5..9，B 有 3..7
              │
       A 发 8..9 给 B，B 发（无）给 A
              │
       双方折叠 → 相同状态（最终一致）
```

- **单写者前提下**：复制只是「把写者的事件同步给读者」，无冲突。
- **多写者（R2）**：见 `local-first.md` §5——分区 + 逻辑单写 + 少量字段 CRDT，不对事件流用通用 CRDT。

## 6. 协议要素（信封）

| 要素 | 作用 |
|---|---|
| `protocolVersion` | 协议版本（P9） |
| `type` | `command` / `event` / `ack` / `resume` / `handoff` |
| `sessionId` | 会话标识 |
| `seq` | 事件序号（幂等去重、续传） |
| `commandId` | 命令唯一 ID（幂等/去重） |
| `expectedVersion` | 预期状态（乐观并发，`if-match`） |
| `expiresAt` | 命令有效期（过期即拒绝） |
| `aggregateId` / `aggregateVersion` | 聚合内序号 |
| `producer` / `principal` | 生产者与主体（宿主附加） |
| `payload` | 内容（事件/命令） |
| `sig` | 签名/鉴权（证明来自可信节点） |

**幂等**：事件不可变，重复投递按 `(sessionId, seq)` 去重；**命令**按 `commandId` 去重（见 §6.1），两者不是一回事。
**续传**：`resume(lastSeq)` → 对端从 `lastSeq+1` 开始补发。
**心跳**：检测断线，触发重连/降级。

### 6.1 命令的幂等与过期

命令会跨网络重发、会离线排队，因此必须自带幂等与过期语义（回应「远程命令没有幂等与过期语义」）。

- **命令 ID 持久去重**：每个命令带唯一 `commandId`。同一 `commandId` 重发，返回**同一结果**，**不重复执行**；去重记录需持久化（跨重启仍有效）。
- **预期状态**：`expectedVersion`（`if-match`）表达命令基于哪一版状态。版本不匹配 → **拒绝**，而不是盲目执行（避免覆盖他人已做的变更）。
- **有效期**：超过 `expiresAt` 的命令 → **拒绝**。离线排队的审批/取消**不能过期后生效**——用户批准的是一个当时的动作，不是一条无限期有效的许可。
- **例子**：「启动 Run」已执行但确认丢失 → 客户端重发**同一 `commandId`** → 返回原结果，**不会启动两次**。
- **两类去重别混**：**事件**去重按 `(sessionId, seq)`；**命令**去重按 `commandId`。

## 7. 断线与恢复

| 情况 | 处理 |
|---|---|
| 外壳断线 | 前端显示「连接断开」；重连后 `resume(lastSeq)` 续传 |
| 写者节点离线 | attach 者只读缓存；命令排队或提示「写者离线」 |
| 复制中断 | 按 seq 续传，无需重传全部 |
| 换端中失败 | 见 `handoff.md` 的回滚 |

- **离线命令排队**：写者离线时命令可排队，但**重连后按 `expiresAt` 校验**——过期命令**拒绝**，不补执行。排队的审批/取消尤其如此：过期即失效，不会「迟到的批准」生效（§6.1）。

---

## 8. 安全

- **传输加密**：跨机一律 TLS；同机进程内可复用本地 IPC。
- **鉴权**：连接需证明持有节点私钥。
- **最小暴露**：节点只对**已配对**的节点开放 attach/复制；默认拒绝。
- **能力边界**：远程 attach 的外壳只能发**被允许的命令**（如只读视角不能发写命令）。
- **审计**：谁在何时 attach、发了什么命令，留痕。

## 10. 反模式

- ❌ **设计成「必须有中心服务器」** → ✅ 对等节点，服务器可选（ADR-0004）。
- ❌ **外壳直接写远端会话** → ✅ 发命令给写者，由写者转事件。
- ❌ **传「当前状态」而非事件** → ✅ 传事件日志，按 seq 续传。
- ❌ **每套传输各写一份协议** → ✅ 同一套「命令 + 事件」契约，传输只是适配器。
- ❌ **隐式信任（谁连上都行）** → ✅ 显式配对 + 鉴权。
