# 换端继续（Handoff）

> 状态：🌿 · 最后更新：2026-11-08
> 上游：ADR-0002（事件溯源）、ADR-0004（对等节点）、`50-distributed/topology-and-sync.md`
> 关联：`20-domain/domain-model.md` §9（Session/Handoff 不变量）、`40-runtime/agent-loop.md` §8（检查点）
> 定位：**预留能力 R1**（v1 不实现，但架构已为其留门）

---

## 0. 一句话

**换端 = 把整个 Session 的「所有权 + 检查点」原子地转移到另一个节点，在那边继续跑；其进行中的 Run 与全部子 Run 随它一起走。** 这是「进行中的任务换端继续」的实现方式；它**不需要推翻单写者模型**，而是把「写者」从 A 原子地换成 B。

---

## 1. 本质：Session 为单位的所有权转移，不是状态合并

```
   ┌── 节点 A（旧写者）────┐                  ┌── 节点 B（新写者）────┐
   │  Session S（写者）      │  ── 转移所有权 ──▶ │  Session S 继续        │
   │  其 Run 正在 Running    │                  │  补齐 seq 0..N 事件     │
   │  事件 seq 0..N          │                  │  从检查点 M 续跑        │
   │  检查点 @seq M          │                  │                       │
   └────────────────────────┘                  └───────────────────────┘
       转移前：A 是唯一写者                          转移后：B 是唯一写者，A 转只读
```

- **同一时刻只有一个写者**（`I-2-1`）保持不变。
- 转移是**原子**的：要么 A 还是写者，要么 B 是写者，**不存在双写**（`I-9-2`）。
- 迁移的是**事件 + 检查点**，不是运行中的进程状态。
- **换端以整个 Session 为单位**（ADR-0011）：转移 `ownerNodeId`，复制整条会话日志；其进行中的 Run 与全部子 Run **随它一起走**（`I-9-4`）。
- **Run 不单独转移**；**Task 是跨会话的组织单位**，「指派 Task」是组织与协作，**不等于**搬迁其关联的 Session。
- 首版**不承诺跨多 Session 的原子转移**：一次只交接一个 Session。

---

## 2. 为什么架构早已支持（前置条件）

换端能「不推翻现状」地加上，是因为前面几个决定：

| 前置 | 来源 | 作用 |
|---|---|---|
| 会话/运行事件溯源 | ADR-0002 | 迁移 = 复制事件（按 seq），天然可续传 |
| Session 是同步与所有权单位 | ADR-0011 / `domain-model.md` §1 | 换端转移整个 Session，Run 随 Session 移动 |
| 检查点机制 | `agent-loop.md` §8 | 有可恢复的快照，B 能接续 |
| 对等节点 + 统一传输 | ADR-0004 / `topology-and-sync.md` | 两节点可直连、可鉴权、可传事件 |
| 工具幂等 | `agent-loop.md` §8 | 续跑可能重放未完成的调用，需幂等 |

> **这就是把「换端」设计成「预留」而非「重写」的原因**——地基已经在了。

---

## 3. 流程（安全暂停点 + 三阶段）

**Offer 前：A 先到达安全暂停点。** 安全暂停点 = **没有进行中副作用**的边界（模型调用、工具调用、子进程都已结束或已确认结果）。A 在此时**补齐最终事件到 `seq M`**，检查点也对应 `M`。

```
   ⓪ Pause      A 到达安全暂停点，补齐最终事件到 seq M
                     ↓（此后 A 不得再产生新事件）
   ① Offer      A ──「把 Session S 交给你，检查点 @seq M」──▶ B
                     （附带：事件 seq 0..M 的校验和、预算剩余、能力需求、资源清单）
   ② Accept     A ◀──「检查点与事件校验一致，我接受」────── B
                     （B 先本地落一份事件 + 检查点）
   ③ Commit     A 持久化提交决策 → 通知 B → B 从 seq M 续跑
                     ↓
                 B 回「已接手」确认 → A 收到确认才转只读
```

- **复制检查点 `M` 之后、提交之前，A 不得继续产生新事件**（暂停）。若因竞态已产生尾部事件（`M+1..M′`），必须把它们一并补齐、并把检查点推进到 `M′`；补不齐就宁可放弃本次转移，而不是带着「半截尾巴」交接。
- **提交决策必须持久化**：A 在提交前把「决定提交 / 提交给哪个节点 / `handoffId`」写进**本地决策记录**（不能只放内存）。崩溃重启后以该记录为准，避免「以为没提交、继续写」或「以为提交了、其实没有」。

**关键：第 ③ 步是提交点**。提交前，A 仍是写者（B 只是「备好」）；提交后，B 成为写者（A 停止）。这是把「双写窗口」压到零的方式。

---

## 4. 校验（防半吊子状态）

- **事件校验**：B 校验收到的 `seq 0..M` 与 A 声明的校验和一致（`I-9-3`）。
- **检查点校验**：检查点必须对应同一 `seq M`，否则拒绝。
- **预算校验**：剩余预算随转移；B 继承同一 `maxSteps/maxCost/maxWallTime`（超限一样停）。
- **能力校验**：B 需具备该 Run 所需的能力/工具；缺 → 拒绝转移（或降级提示）。

**资源清单校验**（事件 + 检查点不足以迁移一个真实任务——编码任务还依赖文件、工作区、工具与凭据）：

| 资源 | 检查什么 | 不满足时 |
|---|---|---|
| **Blob 引用** | 事件引用的每个 Blob 是否可获取、可传输 | 拒绝；不迁移悬空引用 |
| **工作目录 / 仓库状态** | 路径是否存在、未提交修改是否随迁、大文件如何处理 | 明确声明随迁范围；无法保证则拒绝 |
| **工具与插件版本** | 目标端是否有 `pinnedVersions` 要求的版本 | 版本不匹配 → 显式报告，不静默续跑（`I-3-7`） |
| **凭据绑定** | 目标端是否有等效凭据（Keychain 不随迁） | 缺失则相关工具不可用：明确拒绝该能力，或经用户确认后降级 |
| **路径映射** | 源/目标工作目录路径不同时如何映射 | 无法映射 → 拒绝 |

- **无法迁移的资源 → 明确拒绝转移**，**不留半吊子状态**：宁可这次不换端，也不交出一个「看起来能跑、实际缺东西」的 Session。

任一校验失败 → **拒绝**，Session 留在 A（fail-safe，不产生「半转移」）。

---

## 5. 失败与回滚

| 失败点 | 行为 |
|---|---|
| ① Offer 后 B 无响应/拒绝 | A 继续跑，Session 不变 |
| ② Accept 后校验失败 | 拒绝；A 继续跑 |
| ② 之后、③ 之前 A 崩溃 | A 重启后**核对本地决策记录**：无提交记录 → 仍持有 Session；有提交记录 → 进入核对 |
| ③ 提交后 B 崩溃 | B 重启后从检查点续跑（常规恢复） |
| 网络在 ③ 中断 | 提交决策已持久化 → **暂停并核对**；核对完成前**两节点都不得继续执行**；**绝不允许 A 自行恢复为写者**（B 可能已收到提交并开始执行） |
| B 收到提交但确认丢失 | A 超时未收到确认 → 进入核对（查持久化决策 + B 的实际状态），不得自行转只读、也不得继续写 |

**旧写者失效确认**：B 收到提交后必须回一个确认（`HandoffAccepted` / `OwnershipAcked`）；**A 收到该确认才转只读**。超时未收到确认 → 进入核对，而不是默认「自己仍是写者、继续跑」。

**原则**：**提交结果不确定时不猜**——暂停并核对持久化的提交决策；在核对完成前，两节点都不得继续执行。**绝不能让旧写者自行恢复**，也不让 Session 同时被两个节点认领。

---

## 6. 幂等与副作用（最难的部分）

转移后 B 可能**重放**「A 已发起但结果未确认」的工具调用。**单靠「记下已执行标记」不够**——在「执行成功但记录未落盘」的窗口里它不可靠。按能力分档（与 `agent-loop.md` §8.1 一致）：

| 能力或状态 | 恢复行为 |
|---|---|
| 外部系统支持**幂等键** | 用同一个键重试同一次逻辑操作 |
| 外部系统支持**查询执行结果** | 先查结果，再决定是否重试 |
| 可以**证明操作未执行**（进程未启动 / 前置校验失败） | 重新校验授权后重试 |
| 可能已执行、无法查证且非幂等 | 标记 `OutcomeUnknown`，Run 进入 `AwaitingReconciliation`，**暂停依赖它的后续动作** |

- **核对界面**须给出目标、调用时间、已有证据，帮助用户判断实际结果。
- **不能统一自动重试**：普通 shell 命令、发送/发布操作无法保证「自动恢复且绝不重复」——文档承认这个边界，而不是假装能兜住。
- **安全暂停点 / 检查点选在「无进行中副作用」的边界**，减少重放面。

> 这是「多步动作像分布式事务」的体现（`awesome-architecture/tutorial/11`）。换端把这个问题从「理论」变成「必须处理」。

---

## 7. 与 attach 的区别

| | attach | handoff |
|---|---|---|
| 写者 | 不变（远端仍是写者） | **转移**（写者从 A 变 B） |
| 用途 | 在别的端看/控 | 在别的端**继续执行** |
| 复杂度 | 低（只读 + 命令） | 高（所有权 + 校验 + 幂等） |
| 版本 | v1 | R1（预留） |

> 一句话：**attach 是「遥控」；handoff 是「接力」。**

---

## 8. 为什么值得预留（而不是不做）

- 它是「本地优先 + 多端」的自然延伸：任务不该被设备绑死。
- 它**复用**已有地基（事件日志、检查点、对等传输），边际成本主要在协议与幂等，而非重写。
- 它是 R2（复制）、R3（团队节点）的前置技术之一。

## 9. 反模式

- ❌ **搬运运行中的进程状态** → ✅ 迁移事件 + 检查点。
- ❌ **双写窗口** → ✅ 三阶段提交，压到零。
- ❌ **不校验就转移** → ✅ 事件/检查点/预算/能力 + 资源清单校验。
- ❌ **忽略重放副作用 / 只记「已执行」标记** → ✅ 按能力分档；未知则 `OutcomeUnknown` + 待核对。
- ❌ **提交决策只放内存** → ✅ 持久化本地决策记录。
- ❌ **失败时两边都认领 / 不确定就归 A** → ✅ 暂停并核对持久化决策，核对完成前两节点都不继续。

## 10. R1 准入条件（必须满足才能实现 R1）

以下不是「可以以后再补」的优化项，而是 R1 能被称为「安全换端」的**前提**。缺任何一条，都不应把 R1 标成可用。

| # | 准入条件 | 不满足的后果 |
|---|---|---|
| 1 | **安全暂停点定义**：明确「无进行中副作用」的可判定边界 | 转移时仍可能有在途工具调用，重放面不可控 |
| 2 | **尾部事件补齐**：暂停后到检查点之间的事件必须补齐到 `M`（或 `M′`） | 交接出「事件有缺口」的 Session，B 重建出错 |
| 3 | **持久化提交决策**：提交决定写入本地决策记录，跨崩溃可查 | 重启后误判提交状态，导致双写或误放弃 |
| 4 | **旧写者失效确认**：B 收到提交后回确认，A 收到才转只读 | A 不知道 B 是否接手，可能继续写 |
| 5 | **资源清单与路径映射**：Blob / 工作区 / 插件版本 / 凭据 / 路径逐项校验 | 迁移成功但跑不起来（缺文件、缺工具、缺凭据） |
| 6 | **命令幂等（`commandId`）**：命令可去重、可校验 `expectedVersion`、可过期 | 重发导致重复执行，离线命令过期后仍生效 |
